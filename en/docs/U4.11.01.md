# DEBUT procedure

## 1 Purpose

Allocate the memory, disk and file resources.

An execution is a set of commands that begins with DEBUT and ends with FIN [U4.11.02] (see also the POURSUITE procedure [U4.11.03]).

The DEBUT command does the following:

- defines the characteristics of the databases (managed by JEVEUX) and allocates the associated files,
- reads the element and command catalogs.

The apparently complex syntax of this procedure should not worry the user; calling it with the default operands, which is enough in most cases, is: DEBUT ( )

## 3 Printouts

At the start of the execution, a header is printed. It contains:

- the exact identification of the version used: version number, date of the last changes,
- the date and time the execution started,
- the name, architecture and operating system of the machine,
- the language used for the messages,
- the kind of parallelism available (MPI/OpenMP) and the number of processors allocated,
- the version of the libraries used (when available) for hdf5, med, mumps, scotch,
- then several items of information on how the memory is shared out. For example:

```text
Mémoire limite pour l'exécution : 256.00 Mo
consommée par l'initialisation : 148.68 Mo
par les objets du jeu de commandes : 17.48 Mo
reste pour l'allocation dynamique : 89.84 Mo
Taille limite des fichiers d'échange : 48.00 Go
```

This means:

- 256 MB is the amount of memory requested by the user; it is the total amount that must not be exceeded.
- 148.68 MB is used just by starting the execution (loading the executable, the associated dynamic libraries, etc.).
- 17.48 MB is used by reading the command file and loading the element catalog.
- 89.84 MB is the amount of memory available (at this moment) for the objects of the calculation (equal to 256-148.68-17.48). So the calculation cannot start if this value is too small.

During the execution, depending on the dynamic allocations made, when this value changes by more than 10 % (up or down), a message of this kind informs the user:

```text
La mémoire consommée actuellement hors JEVEUX est de 214.08 Mo.
La limite de l'allocation dynamique JEVEUX est fixée à 41.92 Mo.
```

At the end of the execution, a summary says whether the same calculation can be run again with less memory:

```text
La mémoire demandée au lancement est surestimée, elle est de 256 Mo.
Le pic mémoire utilisée est de 216.02 Mo.
```

or whether more memory is needed (depending on the platform, the maximum limit can be exceeded without the system stopping the calculation):

```text
La mémoire demandée au lancement est sous-estimée, elle est de 256 Mo.
Le pic mémoire utilisée est de 273.22 Mo.
```

## 4 Operands

### 4.1 Keyword IMPR_MACRO

```text
IMPR_MACRO =
```

Allows or not the printouts produced by macro-commands in the message file. Message files can be tedious to read when they hold every echo of the sub-commands generated by the macro-command itself. By default, only the echo of the commands the user called explicitly in the command file appears.

### 4.2 Keyword LANG

Chooses the language of the messages printed by the code. If the keyword is not given, the environment variables determine the language of the messages (reference: http://www.gnu.org/software/gettext/manual/gettext.html#Users). For example, one can set in the file ~/.bashrc: export LANG=fr_FR.UTF-8.

<!-- page 5 -->

The encoding (UTF-8 or ISO-8859-1) makes accented characters print correctly. The keyword LANG expects a two-letter value, for example 'FR' (for French) or 'EN' (for English). When a language is chosen (by the environment or by LANG), the file of translated messages (.mo file) must also be available. This file is expected under this name:

```text
$ASTER_ROOT/share/locale/`lang`/LC_MESSAGES/aster_`version`.mo
```

where $ASTER_ROOT is the main directory of Code_Aster (e.g. /aster or /opt/aster), lang is the lowercase name of the language (e.g. en, fr, de...) and version is the name of the Code_Aster version used (e.g. stable, testing, unstable). If the translation file cannot be read, French is used.

Note: even if the translation file exists, a message that has not been translated is printed in French (the language the messages are written in in the source code).

### 4.3 Keyword BASE

```text
BASE =
```

This keyword redefines the parameters of the direct-access files associated with the "databases" when the default ones are not wanted.

Default values of the parameters associated with the databases.

```text
GLOBALE
   NMAX_ENRE                         62914
   LONG_ENRE                          100    Kmots
   LONG_REPE                         2000
VOLATILE
   NMAX_ENRE                         62914
   LONG_ENRE                          100    Kmots
   LONG_REPE                         2000
```

A word is 8 bytes on a 64-bit platform, 4 bytes on a 32-bit platform.

Under Linux 64, with the default values, the DEBUT procedure allocates a direct-access file of at most 62914 records of 100 Kwords (K is 1024) for the 'GLOBALE' database.

Note:

The real size of the file is dynamic; it depends on the volume of information actually stored. This size is limited by the operating conditions and by a parameter among the values that characterize the platform. On the reference Linux 64-bit platform, the initial size is set to 48 GB. This value is used to size 2 objects used by the memory manager, and it is changed automatically during the execution if needed. It can be changed by passing an argument on the command line of the executable after the keyword « -max_base taille », where `taille` is a real value in MB. For the Globale database, which can be saved and reused as input of a calculation, the initial maximum size in « POURSUITE » is kept as it is if the parameter « -max_base » is not used, but it can be redefined in this way if needed.

#### 4.3.1 Operand FICHIER

```text
♦  FICHIER =
```

Symbolic name of the database concerned.

<!-- page 6 -->

#### 4.3.2 Operands LONG_ENRE / NMAX_ENRE / LONG_REPE

Definition of the database parameters (direct-access files).

```text
/  |   LONG_ENRE = lenr
```

lenr is the record length, in Kwords, of the direct-access files used.

Note:

The JEVEUX memory manager uses this parameter to tell two kinds of objects apart: large objects, which are split into as many records as needed, and small objects, which are accumulated in a buffer the size of one record before being unloaded.

```text
|  NMAX_ENRE = nenr
```

nenr is the default number of records. This value is determined from LONG_ENRE and from an operating parameter, set on the reference Linux 64 platform to 48 GB (51 539 607 552 bytes), for the maximum size of the file associated with a database, unless this value was changed with the keyword –max_base on the command line of the executable.

Note:

The two operands LONG_ENRE and NMAX_ENRE must be used with care: misuse can stop the program abruptly when the direct-access files are full. The consistency between the maximum file size and the product of the two parameters LONG_ENRE and NMAX _ENRE is checked at the start of the execution.

```text
|  LONG_REPE = lrep
```

lrep is the initial length of the directory (maximum number of objects JEVEUX can address). The memory manager manages it dynamically and extends the directory and all the associated system objects as needed.

Note:

If the user chooses to change these parameters, this permanently fixes some characteristics of the GLOBALE database, which can no longer be changed in POURSUITE .

### 4.4 Keyword CODE

```text
CODE =
```

This keyword is meant only for the command files of the non-regression tests managed with the source code. Its presence automatically sets the debug mode DEBUG(JXVERI='OUI',), which runs checks on the JEVEUX objects and can add to the run time. The behavior in case of error can be changed.

#### 4.4.1 Operand NIV_PUB_WEB

```text
♦   NIV_PUB_WEB = 'INTRANET'
```

Publication level indicator. Means that the test may only be distributed on the internal network.

```text
NIV_PUB_WEB = 'INTERNET'
```

Means that the test may be distributed as it is on the external network.

### 4.5 Keyword ERREUR

Changes the behavior of the code in case of an <F> error.

<!-- page 7 -->

#### 4.5.1 Operand ERREUR_F

In case of error, the code interrupts the normal execution of the command file. By default, an exception is then raised (for the detailed definition of a Python exception, see the Python documentation or that of the supervisor, cf. [U1.03.01]). In this case, the code executes the FIN command (cf. [U4.11.02]), which closes the database so that the calculation can be continued later. Note that although the initial error is called « fatale » (<F>), the diagnostic is <S>_ERROR because the exception is « caught » by FIN. The study manager then copies this database. This is the behavior when ERREUR_F='EXCEPTION'.

ERREUR_F='ABORT' explicitly asks the code to stop the execution of the command file for good in case of a fatal error (<F>). The FIN command is not executed, so the database is not closed correctly, it is not copied, and the calculation cannot be resumed.

Notes: when developers run test cases, stopping by ABORT is automatic and the default. This is turned on by the presence of the factor keyword CODE (unless ERREUR_F says otherwise).

When CPU time or memory runs out, and for all <S> errors and exceptions, the behavior is the one described for ERREUR_F='EXCEPTION' .

### 4.6 Keyword IGNORE_ALARM

```text
IGNORE_ALARM =
```

Lets the user suppress the printing of some warnings (whose origin the user knows) so as to spot more easily the other warnings that may appear. When the FIN command runs, a summary table of the warnings issued during the execution (with their number of occurrences) is always printed. The warnings ignored by the user are preceded by '*' to tell them apart (and they appear even if they were not issued). Warnings are designated by the identifier printed between the characters < and >, for example: IGNORE_ALARME = ('MED_2', 'SUPERVIS_40',...).

### 4.7 Keyword DEBUG

```text
DEBUG =
```

Debugging option (reserved for developers and code maintenance).

#### 4.7.1 Operand JXVERI

```text
JXVERI =
```

Checks the integrity of the memory segments between two consecutive command executions. By default the execution runs without "DEBUG". This option is always on when the keyword CODE is present.

#### 4.7.2 Operand ENVIMA

```text
ENVIMA = 'TEST'
```

Prints in the RESULTAT file the values of the parameters defined in the ENVIMA package that characterize the machine [D6.01.01].

#### 4.7.3 Operand JEVEUX

```text
◊JEVEUX =
```

<!-- page 8 -->

Turns on the debug mode of the JEVEUX memory manager: unloads to disk are not deferred and value segments are set to an undefined value [D6.02.01].

#### 4.7.4 Operand SDVERI

```text
SDVERI = ’NON’
```

This keyword is meant for developers. Warning: this feature can add a significant cost to the execution. The keyword triggers the check of the data structures produced by the operators. It is used in the code development procedures, in the non-regression tests. If the keyword CODE is present, this keyword takes the default value 'OUI'.

### 4.8 Keyword MESURE_TEMPS

The keyword MESURE_TEMPS chooses the level of detail of the CPU time printouts written in the message file by the commands that do elementary calculations, solve linear systems, unload objects to disk or do MPI communications.

#### 4.8.1 Operand NIVE_DETAIL

◊ NIVE_DETAIL = 0 no printout. = 1 default printouts. = 2 more detailed printouts:

◊ MOYENNE = 'NON' statistics not printed = 'OUI' statistics printed

### 4.9 Keyword MEMOIRE

The data structures are allocated dynamically; the user gives the resource limits when launching the executable in the access interface.

#### 4.9.1 Operand TAILLE_GROUP_ELEM

```text
TAILLE_GROUP_ELEM = tgrel [défaut: 1000]
```

This parameter gives the maximum number of finite elements of the same type that are gathered in one element group. It affects the memory and CPU performance of the elementary calculations and the assemblies. Increasing tgrel usually saves CPU time. On the other hand, the JEVEUX objects are larger, which may need more memory.

#### 4.9.2 Operand TAILLE_BLOC

```text
TAILLE_BLOC = tbloc [défaut: 800.]
```

This parameter gives the block size of the factorized matrices for the LDLT solver. The size is given in kiloR8 (1 kiloR8 = 1024 reals). It affects the number of input/output operations and therefore the assembly and solution times. By default it is 800 kiloR8, that is 8 default records of the direct-access file associated with the JEVEUX database.

### 4.10 Keyword CATALOGUE

This keyword is reserved for developers. It is used when compiling the element catalogs to get the file as a JEVEUX database.

#### 4.10.1 Operand FICHIER

```text
♦ FICHIER = nfic
```

Can only take the value ' CATAELEM'

#### 4.10.2 Operand UNITE

```text
◊ UNITE = unite
```

Logical unit associated with the element catalogs. The procedures that build the element catalog use the value 4. The file fort.4 is obtained from the content of the catalo source directory with a Python procedure.

### 4.11 Keyword RESERVE_CPU

Reserves a share of the CPU time allotted to the job so that the execution can end cleanly when an Aster command detects that CPU time is running out. This mechanism is useful only for a batch execution of Code_Aster. The reserve can be given as an absolute value or as a percentage of the total CPU time. It is bounded by the value of the keyword BORNE.

<!-- page 10 -->

When the keyword CODE is present, that is for all the non-regression tests, a CPU time reserve of 10 seconds is always imposed if the keyword RESERVE_CPU is absent. After the Code_Aster execution, compression operations, sometimes very costly, may be needed before the result files or the Globale database are transferred.

#### 4.11.1 Operand VALE

Value in seconds subtracted from the total CPU time, on which some global commands rely to stop the execution cleanly.

#### 4.11.2 Operand POURCENTAGE

Percentage subtracted from the total CPU time, on which some global commands rely to stop the execution cleanly.

#### 4.11.3 Operand BORNE

Maximum value of the time reserve, 900 seconds by default.
