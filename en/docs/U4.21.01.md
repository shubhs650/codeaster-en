# LIRE_MAILLAGE operator

## 1 Purpose

Create a mesh by reading it from a file. The supported file formats are: ASTER, MED, GIBI, GMSH and IDEAS.

Produces a data structure of type `maillage`.

Important note:

The quality of the mesh read can be checked with the command MACR_INFO_MAIL [U7.03.02] (after LIRE_MAILLAGE).

<!-- page 2 -->

## 2 Syntax

```text
ma [maillage] = LIRE_MAILLAGE
             (  ◊   UNITE =      /  20  ,                  [DEFAUT]
                                 /  i   ,                  [I]
                ◊   FORMAT=      /  ' MED ' ,              [DEFAUT]
                                 /  'ASTER',
                                 /  'GIBI',
                                 /  'GMSH',
                                 /  'IDEAS',
                # Si FORMAT='MED'
                    ◊  NOM_MED      =   mamed ,            [ K*]
                    ◊  INFO_MED     =   / 1,               [DEFAUT]
                                        / 2,
                                        / 3,
                    ◊  PARTITIONNEUR =  / ‘SANS’,          [DEFAUT]
                                        / ‘PTSCOTCH’
                # Si FORMAT='IDEAS'
                    ◊  CREA_GROUP_COUL  =  / 'NON',            [DEFAUT]
                                           / 'OUI',
                ◊   VERI_MAIL =  _F (
                          ◊   VERIF =   /  'OUI'  ,        [DEFAUT]
                                        /  'NON'  , ),
                          ◊   APLAT =   /  1.D-3  ,        [DEFAUT]
                                        /  ap     ,        [R]
                ◊   INFO =       /  1   ,                  [DEFAUT]
                                 /  2   ,
             )
```

## 3 Operands

### 3.1 Operand UNITE

```text
◊  UNITE =   i
```

Logical unit of the mesh file. Unit 20 by default.

### 3.2 Operand FORMAT

```text
◊  FORMAT    =  /  'MED'     [DEFAUT]
                /   'ASTER'
                /   'GMSH'
```

This keyword gives the format of the file to read. Three formats are supported today: 'MED', 'ASTER' and 'GMSH'. The 'ASTER' format is described in [U3.01.00]. The 'MED' format, which stands for « Modélisation et Echanges de Données » (modeling and data exchange), is a neutral data format developed by EDF R&D and CEA to exchange data between calculation codes. The data that can be exchanged in this format are meshes and result fields: fields at nodes, fields by element. MED files are binary and portable (they rely on the HDF library, Hierarchical Data Format). Reading a MED file with LIRE_MAILLAGE retrieves a mesh produced by any other code able to create a MED file. It is the recommended format in code_aster and the default one.

Whatever the format, the data read are:

- the list of nodes: number, name, coordinates,
- the list of elements: number, name, type, names of the nodes,
- the list of node groups: number, name, number of nodes, names of the nodes,
- the list of element groups: number, name, number of elements, names of the elements.

Nota:

In a MED file, the nodes and elements are partitioned according to the groups. A partition corresponds to a MED family. In a MED file, the groups are distributed among the families: there are node families and element families. When a MED file is read, the lists of node groups and element groups are built on the fly by decomposing the families.

For GMSH, files in the ASCII 1.0 and 2.0 formats are read.

In GMSH, groups are always numbered. In version 2.0 they are sometimes named as well.

For the GMSH version 1 format, node and element groups are read as follows:

- all the GMSH element groups numbered 1, 2, ... become element groups (GROUP_MA) named GM1, GM2,
- the groups are mutually exclusive: an element cannot belong to several groups.

For the GMSH version 2 format, node and element groups are read as follows:

- only the groups named in GMSH (PhysicalNames section of the msh format) are imported;
- groups can overlap: an element can belong to several groups;
- the GMSH type of the element must be consistent with the GMSH dimension of the group for it to belong to that group (for example a 2-node segment for a 1D group)

### 3.3 Operand VERI_MAIL

<!-- page 4 -->

The keyword VERI_MAIL triggers 3 checks on the mesh:

- no orphan nodes,
- no "duplicate" elements,
- no elements that are too flat.

If these checks fail, the code issues a warning.

By default (that is, without the keyword VERI_MAIL), the checks are made. To skip them, the user writes:

```text
VERI_MAIL = _F (VERIF = 'NON',),
```

A node is declared orphan if it belongs to the connectivity of no element. An element is declared "duplicate" if 2 elements (or more) have connectivities made of the same list of nodes.

The keyword APLAT = ap issues warnings when the mesh contains elements that are too flat.

The flatness of an element is defined as the ratio Amin/Amax, where Amin and Amax are the lengths of the shortest and longest edges of the element. The names of the elements whose flatness is below ap are printed in the 'MESSAGE' file.

Other mesh quality criteria are available through the command MACR_INFO_MAIL [U7.03.02].

### 3.4 Operands for the 'MED' format

```text
◊  NOM_MED = mamed,
```

A MED file can contain several meshes. Each mesh is identified by its name. To read a particular mesh, give its name as the argument of the keyword NOM_MED. Without the keyword, the first mesh found in the file is read. When the file contains only one mesh, there is therefore nothing to give.

Notes:

- In a mesh, an element group can be made of elements of different dimensions (edges, faces or volumes).
- Such a group shows in Salome (Mesh module) as several groups with the same name under different categories, but it is in fact a single group in code_aster.

```text
◊  INFO_MED =      /   1,        [DEFAUT]
                   /   2,
                   /   3,
```

Prints specific information on how the MED mesh file is read (number of nodes and elements read, information on the MED families, …):

- INFO_MED = 1: no printout,
- INFO_MED = 2: only printouts about the family / group correspondence,
- INFO_MED = 3: all the information is printed.

```text
◊  PARTITIONNEUR = / ‘SANS’, :         [DEFAUT]
                    / ‘ PTSCOTCH’
```

<!-- page 5 -->

By default ( SANS ), the mesh is not partitioned (sequential and former parallelism).

With PTSCOTCH, a mesh held in a file is partitioned and distributed among the subdomains of a parallel calculation. The mesh is cut into as many subdomains as there are MPI processes. In sequential mode, the keyword is ignored. Warning: for the time being, some POI1 elements are not copied.

### 3.5 Operands for the 'IDEAS' format

```text
◊  CREA_GROUP_COUL
```

The user can ask for element and node groups gathering all the elements and nodes of the same color by giving CREA_GROUP_COUL = 'OUI'. These groups are named COUL_n, where n is the color number in IDEAS.

By default this is not done, so as not to increase the number of element and node groups needlessly.

Notes:

- Only Cartesian coordinate systems are handled.
- Only one Cartesian coordinate system is managed.
- When the IDEAS universal file is converted, the code checks whether the user defined several coordinate systems. If so, a warning message tells the user and asks them to check that all coordinate systems are identical.

### 3.6 Operand INFO

```text
◊   INFO =/   1  ,            [DEFAUT]
           /  2  ,
```

Print level.

```text
Si:INFO = 1
```

  - title of the mesh,
  - number of nodes,
  - number of elements of each type,
  - number of node groups, and for each its name and the number of nodes in the group
  - number of element groups, and for each its name and the number of elements in the group.

If INFO = 2, the following is printed in addition to the information of INFO = 1:

| list of nodes | number, name, coordinates, |
|---|---|
| list of elements | number, name, type, names of the nodes, |
| list of node groups | number, name, number of nodes, names of the nodes, |
| list of element groups | number, name, number of elements, names of the elements. |
