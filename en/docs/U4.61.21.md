# ASSEMBLAGE macro-command

## 1 Purpose

Compute one or more assembled matrices (stiffness, mass, damping …) and one or more assembled vectors.

This command is recommended for creating the result objects needed for dynamic calculations, whether matrices or vectors. It avoids tedious calls to the "basic" commands: CALC_MATR_ELEM [U4.41.01], NUME_DDL [U4.61.01], ASSE_MATRICE [U4.61.22], CALC_VECT_ELEM [U4.61.02], ASSE_VECTEUR [U4.61.23].

Produces one or more data structures of type matr_asse_* and cham_no plus, possibly, a data structure of type nume_ddl.

## 3 Operands

### 3.1 Result objects created by the macro-command

This macro-command creates several typed result objects:

- one matr_asse_* for each occurrence of the factor keyword MATR_ASSE (keyword MATRICE),
- one cham_no for each occurrence of the factor keyword VECT_ASSE (keyword VECTEUR),
- possibly a nume_ddl (keyword NUME_DDL) if it does not already exist.

Consider for example the sequence:

```text
...
```

# nu is not yet an existing result object.

```text
ASSEMBLAGE   (MODELE = mo , ...
                NUME_DDL = CO( " nu " ),
                MATR_ASSE = ( _F( MATRICE= CO("K"), OPTION='RIGI_MECA'),
                VECT_ASSE = ( _F( VECTEUR= CO("F"), OPTION='CHAR_MECA'))
ASSEMBLAGE   (MODELE = mo , ...
                NUME_DDL = nu,
                MATR_ASSE = (_F(MATRICE=CO( "M") ,OPTION='MASS_MECA'),
                                 _F(MATRICE=CO( "A") ,OPTION='AMOR_MECA'),
),)
```

the 1st call to ASSEMBLAGE creates 1 MATR_ASSE: K

```text
1VECT_ASSE : F
1NUME_DDL : nu
```

the 2nd call to ASSEMBLAGE creates 2 MATR_ASSE: M and A

Remark:

In the 2nd call, the nume_ddl result object is given (it exists; it was created by the 1st call). In this case, it is assumed to suit the 2 matr_asse to be created; it is therefore important that the nume_ddl is first computed for an option of the " RIGIDITE " (stiffness) kind, so that it contains the Lagrange nodes of the restraint loads (see CALC_MATR_ELEM [U4.61.01]).

In the preceding example, the 3 matr_asse K , M and A and the vector F rest on the same numbering of the unknowns ( nu ). This is a necessary condition for the mode-shape search algorithms.

### 3.2 Operands MODELE / CHAM_MATER / CARA_ELEM / INST

```text
♦  MODELE = mo
```

This operand indicates the elements for which the element calculations must be done: recall that most of the finite elements are defined in the model.

There are a few exceptions:

1) The elements that enforce the DIRICHLET conditions with Lagrange multipliers, that is, the elements used to impose conditions on the displacement degrees of freedom in mechanics, the temperature degrees of freedom in thermal analysis and the pressure degrees of freedom in acoustics. 2) The nodal load elements, the thermal exchange elements between walls, ...

These elements are defined in the result objects of type char_meca, char_ther or char_acou.

The argument l_char must therefore be given for the calculation of the assembled stiffness matrices: RIGI_MECA, RIGI_THER, RIGI_ACOU, RIGI_MECA_HYST and RIGI_THER_CONV(_D).

<!-- page 5 -->

```text
◊  CHAM_MATER = chmater
```

Name of the material field where the material properties of the elements are defined.

This argument is almost always needed.

In practice, it can be left out:

  - for discrete elements whose element matrices are defined in the cara_elem result object. See AFFE_CARA_ELEM [U4.42.01],
  - for the calculation of the stiffnesses due to the Lagrange-multiplier enforcement of the boundary conditions.

```text
◊  CARA_ELEM = carac
```

The element properties carac are needed if the model contains structural elements (beam, shell or discrete elements) or non-isotropic continuum elements.

```text
◊  INST = tps
```

The argument tps is used when the material properties or the loads depend on time. A fairly frequent case is that of a mechanical material that depends on the temperature, which itself depends on time.

### 3.3 Operands CHARGE

```text
◊  CHARGE = l_char
```

This operand has several distinct functions:

1) specify the elements for which the element stiffness calculations are done (DIRICHLET conditions), 2) for the options 'RIGI_THER_CONV(_D)': give the value of the convection velocity, 3) for the option 'IMPE_MECA': give the value of the acoustic impedance of the boundary elements, 4) for the option 'ONDE_FLUI': give the value of the pressure of the incident wave, 5) for the option 'RIGI_ROTA': give the value of the rotation imposed on the model.

Remark:

Take care with the two CHARGE operands: the one under VECT_ASSE cannot replace the one under ASSEMBLAGE. If only CHARGE under VECT_ASSE is given, the loads are not taken into account in the functions below.

When the macro-command is called to assemble vectors with an input nume_ddl result object (under the keyword NUME_DDL), the value of the keyword CHARGE l_char must be identical to the one used to create the nume_ddl.

Consider for example the following sequence:

```text
...
```

# nu is not yet an existing result object.

```text
ASSEMBLAGE   (MODELE = mo , CHARGE = (char_1,char_2),...
              NUME_DDL = CO( " nu " ),
              MATR_ASSE = ( _F( MATRICE= CO("K"), OPTION='RIGI_MECA'))
```

# nu exists and is an input result object.

```text
ASSEMBLAGE   (MODELE = mo , CHARGE = (char_1,char_2),...
              NUME_DDL = nu,
              VECT_ASSE = (  _F(VECTEUR=CO( "F") ,OPTION='CHAR_MECA',
                                 CHARGE=CHAR_F),),)
```

### 3.4 Operand CHAR_CINE

```text
◊  CHAR_CINE = lchci
```

This operand avoids "dualizing" (enforcing with Lagrange multipliers) some Dirichlet boundary conditions (restraints). These will be eliminated.

### 3.5 Operand NUME_DDL

```text
♦  NUME_DDL  =  nu
```

The user of the macro must always give a result object name after the keyword NUME_DDL. If the result object does not exist, it is created.

If the result object exists, it is used to number the matrices.

### 3.6 Keyword MATR_ASSE

This factor keyword requests the calculation of an assembled matrix (at each occurrence).

The name of the assembled matrix is given by the operand MATRICE and the "nature" of the matrix is defined by the operand OPTION.

The possible options: 'RIGI_MECA', 'MASS_MECA', … are described in [U4.61.01].

The choice of the option determines the type of the resulting matr_asse_* [U4.61.01].

#### 3.6.1 Operands specific to some options

##### 3.6.1.1 Operand MODE_FOURIER

```text
◊  MODE_FOURIER = nh
```

Positive or zero integer giving the FOURIER harmonic on which the matrices are computed.

By default: nh = 0

##### 3.6.1.2 Operand SIEF_ELGA (option 'RIGI_GEOM')

```text
♦  SIEF_ELGA = sig
```

The stress field sig given for the calculation of the option 'RIGI_GEOM' must have been computed with the option 'SIEF_ELGA' (stress field at the GAUSS points of the elements) (see commands CALC_CHAM_ELEM [U4.81.03] or CALC_CHAMP [U4.81.04]).

##### 3.6.1.3 Operand GROUP_MA (options 'MECA_GYRO' and 'RIGI_GYRO')

```text
◊  GROUP_MA =   grma
```

The calculation of the options 'MECA_GYRO' and 'RIGI_GYRO' can be restricted to the elements specified by GROUP_MA.

##### 3.6.1.4 Operands AMOR_FLUI, VNOR and TYPE_AMOR

```text
◊  AMOR_FLUI =
```

This option deactivates the contribution of the fluid absorbing boundaries ('3D_FLUI_ABSO', '2D_FLUI_ABSO' and 'AXIS_FLUI_ABSO'). In particular, when the u−p−φ fluid formulation is used in a harmonic calculation, the contribution of the fluid absorbing boundaries can be taken into account through the calculation of a third-order matrix (with the option IMPE_MECA). This third-order matrix can be used only in a harmonic calculation (operand MATR_IMPE_PHI in DYNA_VIBRA) and makes the matrix symmetric (unlike the calculation of this contribution through AMOR_MECA). The option AMOR_FLUI = 'NON' avoids computing this contribution twice. By default, AMOR_FLUI = 'OUI'. This operand is available only for the option AMOR_MECA.

<!-- page 7 -->

```text
◊  VNOR =
```

This option takes into account the case of an emitting boundary. The most common case is the radiating one (or partially radiating if a reflection coefficient α≠0 is defined). For a radiating boundary VNOR = 1. (option active by default). For an emitting boundary VNOR = - 1 . This coefficient multiplies the value of the impedance of the fluid absorbing boundaries ('3D_FLUI_ABSO' , '2D_FLUI_ABSO' and 'AXIS_FLUI_ABSO'). This operand is available only for the options AMOR_MECA , IMPE_MECA and AMOR_ACOU.

```text
◊  TYPE_AMOR =
```

This option computes either all the damping sources present in the model or only the source related to the absorbing boundary elements (fluid or not). The default option ( TYPE_AMOR = 'TOUT' ) takes into account any Rayleigh damping, the damping coming from the discrete elements and that coming from the absorbing boundary elements. In this case either the mass and stiffness matrices for the Rayleigh damping (and the material field), or the properties of the discrete elements, must be given. If the only damping is the one coming from the absorbing boundary elements, TYPE_AMOR = 'ABSO' must be given, with only the material field as input. This operand is available only for the option AMOR_MECA .

### 3.7 Keyword VECT_ASSE

This factor keyword requests the calculation of an assembled vector (at each occurrence).

The name of the assembled vector is given by the operand VECTEUR.

Of the possible element calculation and vector assembly options, only some of all those offered in the commands CALC_VECT_ELEM and ASSE_VECTEUR are offered here: 'CHAR_MECA' for mechanical physics, 'CHAR_THER' and 'CHAR_ACOU' for thermal and acoustic physics respectively.

The set of options and associated operands is described in [u4.61.02] and [u4.61.23].

Remark:

The option 'FORC_NODA' and the handling of a model that contains substructures under the option 'CHAR_MECA', often used in statics, are not available in this macro-command.

#### 3.7.1 Operands specific to some options

##### 3.7.1.1 Operand MODE_FOURIER

```text
◊  MODE_FOURIER = nh
```

Positive or zero integer giving the FOURIER harmonic on which the vectors are computed for mechanical physics.

By default: nh = 0

<!-- page 8 -->

##### 3.7.1.2 Operand CHARGE

```text
◊  CHARGE = l_char_v
```

This operand gives access to the load information specific to each vector. The values of l_char_v complete ( by addition ) the loads l_char given under the keyword CHARGE outside the keyword VECT_ASSE.

Remark:

Duplicates between the loads given in l_char and in l_char v are forbidden.

Take care with the two CHARGE operands: the one under VECT_ASSE cannot replace the one under ASSEMBLAGE. If only CHARGE under VECT_ASSE is given, the loads are not taken into account in the functions mentioned in chapter 3.3.

Example of load handling:

```text
ASSEMBLAGE   (MODELE = mo , …
             CHARGE = (char _1,char_2) ,
             NUME_DDL = CO( " nu " ),
             MATR_ASSE = ( _F( MATRICE= CO("K"), OPTION='RIGI_MECA'),
             VECT_ASSE = ( _F( VECTEUR= CO("F1"),
                               OPTION='CHAR_MECA',CHARGE=char_A ),
                           _F( VECTEUR= CO("F2"),
                               OPTION='CHAR_MECA',CHARGE=char_B ),
                           _F( VECTEUR= CO("F3"),OPTION='CHAR_MECA'),)
```

In the example above, the loads assembled for each vector are:

```text
Vecteur                         Charges assemblées
  F1                       char_1, char_2, char_A
  F2                       char_1, char_2, char_B
  F3                       char_1, char_2
```

## 4 Examples

### 4.1 Computation of mechanical mode shapes

```text
ASSEMBLAGE   (  MODELE = mo  ,      CHARGE = ch_blocage ,
                CHAM_MATER = chmat  ,  CARA_ELEM = carac ,
                NUME_DDL = CO( "nu")   ,
      MATR_ASSE = (_F  (MATRICE = CO( "K") , OPTION = 'RIGI_MECA'),
                   _F  (MATRICE = CO( "M") , OPTION = 'MASS_MECA'),),)
modes = CALC_MODES ( MATR_RIGI = K,
                     MATR_MASS = M,
                     ...)
```

### 4.2 Computation of Euler buckling modes

# chsief is the stress field associated with the load

```text
ASSEMBLAGE   (  MODELE = mo  ,      CHARGE = ch_blocage ,
                CHAM_MATER = chmat  ,  CARA_ELEM = carac ,
                NUME_DDL = CO( "nu") ,
        MATR_ASSE = (  _F(MATRICE= CO("K"), OPTION='RIGI_MECA'),
                       _F(MATRICE= CO( "KG"), OPTION='RIGI_GEOM',
                       SIEF_ELGA=chsief),),)
modflamb = CALC_MODES ( MATR_RIGI = K,
                        MATR_MASS = KG,
                        …)
```

### 4.3 Computation of a forced response

```text
ASSEMBLAGE   (  MODELE = mo  ,      CHARGE = ch_blocage ,
                CHAM_MATER = chmat  ,  CARA_ELEM = carac ,
                NUME_DDL = CO( "nu")   ,
      MATR_ASSE = (_F  (MATRICE = CO( "K") , OPTION = 'RIGI_MECA'),
                   _F  (MATRICE = CO( "M") , OPTION = 'MASS_MECA'),),
      VECT_ASSE = ( _F( VECTEUR= CO("F"),
                     OPTION='CHAR_MECA',CHARGE=char_A ),)
reponse = DYNA_VIBRA ( MATR_RIGI = K,  MATR_MASS = M,
                       EXCIT = _F( VECT_ASSE = F, ...)...)
```
