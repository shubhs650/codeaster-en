# IMPR_RESU procedure in the 'RESULTAT' and 'ASTER' formats

## 1 Purpose

Write the mesh or the results of a calculation to a file in the 'RESULTAT' format, or the mesh in the 'ASTER' format.

This procedure currently writes, as chosen:

- a mesh,
- fields at nodes (displacements, temperatures, mode shapes, static modes, …),
- fields by element at nodes or at GAUSS points (stresses, generalized forces, internal variables…).

The procedure IMPR_RESU also writes a mesh and/or results to a file, in particular to view them graphically (cf. documents [U7.05.01] ('IDEAS' format), [U7.05.21] ('MED' format) and [U7.05.32] ('GMSH' format)).

For objects of type `resultat`, only part of the information can be printed, by selecting the fields and the step indexes to use.

For printouts in the 'RESULTAT' format, the topological entities (node groups and element groups) on which the results are printed can be selected. The amount of information printed can also be reduced by asking only for some components, for values in an interval chosen by the user, or for extreme values. All these options can be combined, for example to get the maximum value of a given component on a particular topological entity and in an interval of values chosen by the user.

The 'RESULTAT' format must not be used to store or exchange results: it is not frozen.

## 3 Typography in the IMPR_RESU documentation

To understand the IMPR_RESU documentation, note that in Code_Aster the term ’RESULTAT’ covers three rather different notions:

- an object type,
- a file type,
- an output format.

On the one hand, "result" means the quantities produced by an Aster calculation operator that produces several fields (evolution calculation, mode shape calculation, etc...).

These data (results) are held in an Aster data structure of a generic type called `resultat`. This generic type has subtypes, for example mode_meca, evol_elas, etc., whose storage differs slightly. An object of type `resultat` has only one subtype. In the Aster documentation, object type names are in lowercase Courier.

On the other hand, the results meant for printing, in particular those from IMPR_RESU, go into a file called the RESULTAT file (associated with unit 8, type resu in astk). The output format of this file meant for printing is also called RESULTAT.

In short:

| result | data produced by solving the system, |
|---|---|
| `resultat` | generic name of the object type (of the data structure) that holds the result, |

```text
evol_ther
```

name of the subtype of the result of type `resultat`,

```text
mode_meca
```

| FICHIER | (without quotes) name of the file that holds the results, whatever the format of its content, |
|---|---|
| ’RESULTAT’ | (with quotes) name of the (Aster) format of the file that holds the results. |

## 4 Operands FORMAT, PROC0, UNITE and INFO

The procedure IMPR_RESU writes a mesh and/or result values in different formats, in particular for graphical viewing [U7.05.01], [U7.05.11], [U7.05.21] and [U7.05.31].

The operand FORMAT gives the print format of a result. The default format is 'MED' (cf. [U7.05.21]). It prints the mesh and/or the results as a listing.

The operand PROC0, whose default value is 'OUI', restricts printing to the processor of rank 0. If it is given the value 'NON', all processors print.

The keyword UNITE gives the file the data are written to (cf. command DEFI_FICHIER). By default, the file of logical unit 8 is used in the ’RESULTAT’ format and 26 in the 'ASTER' format.

When the keyword INFO is 2, it gives information on the printouts made by the command.

## 6 Operands CHAM_GD and RESULTAT

The values of the computed fields are stored in data structures called quantity fields. These quantity fields can be directly accessible (cham_gd object) or sit in a data structure that gathers several quantity fields (`resultat` object).

- a quantity field is a data structure that stores fields defined at nodes (cham_no_*) or fields defined by element (cham_elem_*). Among fields by element, there are fields defined at the nodes of the elements and fields defined at the GAUSS points of the elements,
- a `resultat` object is made of one or more quantity fields. For example, at each calculation step the displacement quantity field is stored in the `resultat` data structure. This structure is therefore indexed like an order-2 matrix, one index being for example the list of calculation times and the other the set of computed fields (displacements, stresses, strains, ...). A quantity field is then accessed by giving the value of an access variable (step index, time, frequency, mode number ...) and a field name (’DEPL’, ’SIGM_ELNO’,...). There are several types of `resultat` object: evol_elas, evol_noli, mode_meca,.... Each has its own list of fields and list of allowed access variables. A `resultat` object also carries some complementary results (for example the generalized mass or the modal participation factors in a modal calculation (`resultat` object of type mode_meca)), different for each value of the access variable. These complementary results are called parameters. Given the `resultat` data structure, the printing options available are clearly those of the quantity fields, plus specific ones:
  - information on the data structure (for example: list of the access variables, list of the fields actually computed,...),
  - selective access to a quantity field (for example, printing the displacement field at time t=15.),
  - printing the values of parameters. The operand RESULTAT prints the fields held in a `resultat` object. One can for example choose to print only some fields (see the next keyword: NOM_CHAM) on some components of some nodes (cf. NOEUD_CMP).

## 8 Parameters

### 8.1 Operand TOUT_PARA

This keyword says whether all the values of the parameters attached to the object of type `resultat` are printed. Example:

```text
IMPR_RESU(RESU=(_F(RESULTAT= resu,
       TOUT_PARA= ’OUI’, NUME_ORDRE= 3)))
```

The values of all the parameters are printed in the RESULTAT file, but only for the third calculation step of a `resultat` object of type mode_meca: printout of the parameters of the object resu for step index 3:

```text
NOM_MODE         3
FREQ             1.09787E+4
OMEGA2           4.75843E+09
AMOR_REDUIT      0.00000E+00
ERREUR           2.76853E-10
MASS_GENE        1.50009E-07
RIGI_GENE        7.13806E+02
........
........
NORME            SANS_CMP: LAGR
```

### 8.2 Operand NOM_PARA

This keyword chooses a list of symbolic parameter names among all the possible ones. The keywords TOUT_PARA and NOM_PARA cannot be used together. Example:

```text
IMPR_RESU(RESU=(_F( RESULTAT= resu,
                 NOM_PARA= (’NORME’), NUME_ORDRE= 3)))
```

The value of the parameter named ’NORME’ is printed in the RESULTAT file, but only for the third calculation step of a `resultat` object of type mode_meca: printout of the parameters of the object resu for step index 3:

```text
NORME           SANS_CMP: LAGR
```

### 8.3 Operand FORM_TABL

This keyword chooses the print format of the parameter values: an array whose lines are limited to 80 characters (FORM_TABL = ’OUI’), an array whose lines can reach 2000 characters (FORM_TABL = ’EXCEL’), or a list (one parameter per line) (FORM_TABL = ’NON’). By default the parameters are printed as an array. Example:

```text
1/ FORM_TABL = ’OUI’
       NUME_ORDRE   NUME_MODE       ITER_QR             ITER_BATHE
             FREQ                OMEGA2           AMOR_REDUIT
             MASS_GENE        RIGI_GENE       AMOR_GENE
             MASS_EFFE_DY     MASS_EFFE_DZ    FACT_PARTICI_DX
             FACT_PARTICI_DZ  MASS_EFFE_UN_DX MASS_EFFE_UN_DY
              NORME              METHODE
2/ FORM_TABL = ’EXCEL’
NUME_ORDRE   NUME_MODE        ITER_QR             ITER_BATHE
```

## 9 Selecting components

Another way to reduce the volume of the printouts is to print only the values of some components (for example only the displacement along the X axis: component DX). Note: component selection does not work for fields with sub-points.

### 9.1 Operand TOUT_CMP

This keyword says that all the components of the field are to be printed.

### 9.2 Operand NOM_CMP

This keyword chooses the list of components of the cham_gd, or of all the fields of the result object, to print. The keywords TOUT_CMP and NOM_CMP cannot be used together. These components are described in the specific documentation of the elements.

## 10 Selecting topological entities

To reduce the volume of the printouts, it is sometimes necessary to print only part of the result: a field at nodes only at some nodes, or a field by element only on some elements. Note: selecting topological entities does not work for fields with sub-points.

### 10.1 Operand TOUT

This keyword says that the field is to be printed on the whole structure (all nodes for a field at nodes, all elements for a field by element).

### 10.2 Operand GROUP_NO

This keyword gives the list of node groups on which a cham_no is printed. If it is used when printing a cham_elem, it is ignored, and the cham_elem is printed on all the elements given elsewhere.

### 10.3 Operand GROUP_MA

This keyword gives the list of element groups on which a cham_elem is printed. For a cham_no, it gives the list of nodes, the corner nodes of the elements, at which the cham_no is printed.

<!-- page 8 -->

## 11 Selecting values

It is also useful to print only the extreme values of all or some components, on all or part of the structure.

### 11.1 Operand VALE_MAX

This keyword says that the maximum value of each component of the field is printed, possibly within an interval given by the arguments BORNE_SUP and/or BORNE_INF.

<!-- chunk 6 fr=8e94a42b4e35 method=machine source=session:task-5.2 on=2026-10-30 -->

### 11.2 Operand VALE_MIN

This keyword says that the minimum value of each component of the field is printed, possibly within an interval given by the arguments BORNE_SUP and/or BORNE_INF.

### 11.3 Operand BORNE_SUP

This keyword gives the upper bound of the interval over which the field is printed. All the values of the field below this upper bound are printed.

### 11.4 Operand BORNE_INF

This keyword gives the lower bound of the interval over which the field is printed. The values of the field above this lower bound are printed.

## 12 Printing coordinates: operand IMPR_COOR

This keyword says whether the coordinates of a node are printed when a cham_no is written in the ’RESULTAT’ format.

## 13 Operand FORMAT_R

```text
◊  FORMAT_R  =  /  FORM,
                /  ’1PE21.14’              [DEFAUT]
```

Gives the output format of real values in the ’RESULTAT’ format.

Note: choosing the output format of real values does not work for fields with sub-points.

## 14 Operand PARTIE

```text
◊  PARTIE =  /  ‘REEL’,
             /  ‘IMAG’,
             /  ‘MODULE’,
             /  ‘PHASE’,
```

Gives the print format of complex numbers. If nothing is given, the complex number is printed. Otherwise one can print the real part ( PARTIE=’REEL’ ), the imaginary part ( PARTIE=’IMAG’ ), the modulus ( PARTIE='MODULE' ) or the phase ( PARTIE='PHASE' ).

## 15 Note on fields with sub-points

In Aster there are cham_elem with sub-points (both cham_elem at nodes and cham_elem at Gauss points). In the ’RESULTAT’ format, IMPR_RESU prints cham_elem with sub-points. If a cham_elem has sub-points on some elements and not on others, it is printed in two steps:

- first the cham_elem on all the elements that have no sub-points,
- then the cham_elem on all the elements that have sub-points.

A specific format is used for each of these printouts. Printing of fields with sub-points is « basic »: all the geometric entities, all the components and all the sub-points are always printed (one line per sub-point). Real numbers are always printed with 10 significant digits.

A trick to print more significant digits for a field with sub-points is to call the command POST_CHAMP to extract the field at a particular sub-point, then print the new data structure with the keyword FORMAT_R.

## 16 Printing the mesh: operands MAILLAGE / MODELE

This argument prints the mesh in FORMAT = ’ASTER’ or ’RESULTAT’. The format is then the one used by LIRE_MAILLAGE [U4.21.01] and defined in [U3.01.00]. By default, the whole mesh is printed. The object of type `modele` is optional for most printouts. It can however be used when printing a mesh in the ’ASTER’ or ’RESULTAT’ formats, to print only the part of the mesh whose elements are assigned in the model. With the ’ASTER’ format, the mesh is written to a file of type .mail that LIRE_MAILLAGE can read back. With the ’RESULTAT’ format, the mesh is written by default to the .resu file and cannot be read back by LIRE_MAILLAGE as it is, because the .resu file also contains titles, subtitles and possibly other information.

## 17 Operand SOUS_TITRE

```text

Exem ple:"CHAMPPAR ELEMENT AUX POINTS DE GAUSS"
```
