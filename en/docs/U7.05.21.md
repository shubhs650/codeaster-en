# IMPR_RESU procedure in the 'MED' format

## 1 Purpose

Write the result of a calculation to a file in the MED format. This document describes the keywords of the command IMPR_RESU [U4.91.01] for this output format only.

One can write to a file in the MED format:

- a mesh,
- fields at nodes,
- fields by element.

When fields by element at Gauss points are written, the location of the reference elements (coordinates and weights of the Gauss points) is written too.

MED («Modélisation et Échanges de Données», modeling and data exchange) is a neutral data format developed by EDF R&D and CEA to exchange data between calculation codes. The data that can be exchanged in this format are meshes and result fields at nodes and by element. MED files are binary and portable (they rely on the HDF5 library, Hierarchical Data Format). Writing results to a MED file lets any other calculation code interfaced with MED read the results produced by Code_Aster through the command IMPR_RESU.

## 3 Operands FORMAT, UNITE, PROC0, VERSION_MED and INFO

### 3.1 Operand FORMAT

The operand FORMAT gives the format of the file the result is written to. The format ’MED’ tells the procedure IMPR_RESU that the result must be written to a file in the MED format. It is the default output format. When a new file in the MED format is created, it is written in the MED 3.3.1 format. If the file already exists, its MED format level is kept.

### 3.2 Operand UNITE

Defines the unit the med file is written to. By default, UNITE = 80, which is the default unit of the rmed type in astk.

### 3.3 Operand PROC0

The operand PROC0, whose default value is 'OUI', restricts printing to the processor of rank 0. If it is given the value 'NON', all processors print.

### 3.4 Operand INFO

When the keyword INFO is 2, it gives information on the printouts made by the command.

### 3.5 Operand VERSION_MED

```text
◊  VERSION_MED  =  /’3.3.1’,                         [DEFAUT]
                   /’4.0.0’,
                   /’4.1.0’,
```

When a new file in the med format is created, it is written in the med 3.3.1 format. If the file already exists, its med format level is kept. The MED file version can be changed with the keyword VERSION_MED .

## 4 Factor keyword RESU

This factor keyword gives the results and the fields to print.

### 4.1 Operand MAILLAGE

If the result is a mesh (operand `maillage` [U4.91.01]), the data written to the result file in the MED format are:

  - the list of nodes: number, name, coordinates,
  - the list of elements: number, name, type, names of the nodes,
  - the list of node groups: number, name, number of nodes, names of the nodes,
  - the list of element groups: number, name, number of elements, names of the elements.

Nota: in a MED file, the nodes and elements are partitioned according to the groups. A partition corresponds to a MED family. In a MED file, the groups are distributed among the families: there are node families and element families.

### 4.2 Operand RESULTAT

The operand RESULTAT prints to a MED file fields held in a result object.

The following information is written to the ’MESSAGE’ file:

  - operand ’RESULTAT’,
  - operand ’NOM_CHAM’,
  - operand ’NUME_ORDRE’,
  - name of the field stored in the MED file: the three previous operands concatenated.

If INFO_MAILLAGE = = ‘OUI’, more detailed information is printed in the ‘MESSAGE’ file when the MED mesh is written: for example the element types printed, the names of the MED families created, etc.

### 4.3 Operand CARA_ELEM

The operand CARA_ELEM is used to print fields with sub-points. When CARA_ELEM is given, fields with sub-points are printed with extra information in the MED file that positions the sub-points from the information held in the sd_cara_elem (thickness of a shell, twist angle of a multifiber beam, …).

Note: it is currently not possible to view fields at sub-points on TUYAU elements in the ParaViS module of Salome-Meca. For the time being, the operator IMPR_RESU_SP [U7.05.41] can be used for this.

### 4.4 Operand CHAM_GD

The operand CHAM_GD prints to the file a data structure of type cham_gd. In practice, this keyword can print a map, a field by element or a field at nodes.

### 4.5 Operand NOM_CHAM_MED

The operand NOM_CHAM_MED defines the name of the MED field, a string of 64 characters. This is useful in particular to print some components of a field as several fields in the same MED file (for example to view SIRO_ELEM).

### 4.6 Operand NOM_RESU_MED

The operand NOM_RESU_MED is an alternative to NOM_CHAM_MED for naming the MED fields. With it, the MED fields are no longer named explicitly, which means that all the fields held in the result are printed. Each MED field name is built from:

- the character string given to NOM_RESU_MED (a string of at most 8 characters),
- the symbolic name of the Aster field.

For example:

```text
IMPR_RESU = (
   FORMAT = ’MED’,
   RESU   = _F (RESULTAT      = U,
                NOM_RESU_MED  = ’U_HAUT’,
                GROUP_MA      = ’HAUT’,
                NUME_ORDRE    = 1, )
   )
```

<!-- page 6 -->

If the result U contains the fields DEPL and SIEF_ELGA, the command above produces the MED fields:

```text
•  ’U_HAUT__DEPL’,
•  ’U_HAUT__SIEF_ELGA’,
```

This is useful in particular to print the same field on different element groups in the same MED file.

### 4.7 Operand IMPR_NOM_VARI

This keyword is useful for internal variables. When it is used and a VARI_* field is to be printed, a VARI_*_NOMME field is printed instead. The names of its components are based on the catalog of the constitutive laws used in the calculation. If two constitutive laws have internal variables in common, these are merged into a single component.

### 4.8 Operand PARTIE

Complex fields cannot be written. So one must choose between the real part (PARTIE=’REEL’), the imaginary part (PARTIE=’IMAG’), the modulus (PARTIE='MODULE') or the phase (PARTIE='PHASE').

### 4.9 Operands TOUT_ORDRE / NUME_ORDRE / LIST_ORDRE /

```text
NUME_MODE /  INST /  LIST_INST  / FREQ  / LIST_FREQ  /
NOEUD_CMP / NOM_CAS / ANGLE / PRECISION / CRITERE
```

Cf. document [U4.91.01].

## 5 Selecting components

Another way to reduce the volume of the printouts is to print only the values of some components (for example only the displacement along the X axis: component DX). Note: component selection does not work for fields with sub-points.

### 5.1 Operand TOUT_CMP

This keyword says that all the components of the field are to be printed.

### 5.2 Operand NOM_CMP

This keyword chooses the list of components of the cham_gd, or of all the fields of the result object, to print. The keywords TOUT_CMP and NOM_CMP cannot be used together. These components are described in the specific documentation of the elements.

## 6 Selecting topological entities

To reduce the volume of the printouts, it is sometimes necessary to print only part of the result: a field at nodes only at some nodes, or a field by element only on some elements. Note: selecting topological entities does not work for fields with sub-points.

### 6.1 Operand TOUT

This keyword says that the field is to be printed on the whole structure (all nodes for a field at nodes, all elements for a field by element).

<!-- chunk 5 fr=bf57dcb41ac2 method=machine source=session:task-5.2 on=2026-10-30 -->

### 6.2 Operand GROUP_NO

This keyword gives the list of node groups on which a cham_no is printed. If it is used when printing a cham_elem, it is ignored, and the cham_elem is printed on all the elements given elsewhere.

### 6.3 Operand GROUP_MA

This keyword gives the list of element groups on which a cham_elem is printed. For a cham_no, it gives the list of nodes, the corner nodes of the elements, at which the cham_no is printed.

## 7 Example

```text
IMPR_RESU = (
   FORMAT = ’MED’,
   RESU   = _F (RESULTAT      = REMEZERO,
          NOM_CHAM  = ’ERME_ELEM’,
          NUME_ORDRE   = 3, )
   )
```

Running the command IMPR_RESU prints the following in the ’MESSAGE’ file:

```text
RESULTAT                : REMEZERO
CHAMP                   : ERME_ELEM
NUME_ORDRE              : 3
    ==> NOM MED         : REMEZEROERME_ELEM
```

Example of NOM_CHAM_MED used to print SIRO_ELEM:

```text
IMPR_RESU(FORMAT=’MED’,
          RESU=(
                _F(RESULTAT=RESUNL,
                   NOM_CHAM=(’SIRO_ELEM’,),
                   NOM_CHAM_MED=(’RESUNL__SIRO_ELEM_NORMAL’),
                   NOM_CMP=(’SIG_NX’,’SIG_NY’,’SIG_NZ’,’SIG_N’,),
                   GROUP_MA=’PRES’,),
                _F(RESULTAT=RESUNL,
                   NOM_CHAM=(’SIRO_ELEM’,),
                   NOM_CHAM_MED=(’RESUNL__SIRO_ELEM_TANGENT’),
                   NOM_CMP=(’SIG_TX’,’SIG_TY’,’SIG_TZ’,),
                   GROUP_MA=’PRES’,),
                _F(RESULTAT=RESUNL,
                   NOM_CHAM=(’SIRO_ELEM’,),
                   NOM_CHAM_MED=(’RESUNL__SIRO_ELEM_T1’),
                   NOM_CMP=(’SIG_T1X’,’SIG_T1Y’,’SIG_T1Z’,’SIG_T1’,),
                   GROUP_MA=’PRES’,),
                _F(RESULTAT=RESUNL,
                   NOM_CHAM=(’SIRO_ELEM’,),
                   NOM_CHAM_MED=(’RESUNL__SIRO_ELEM_T2’),
                   NOM_CMP=(’SIG_T2X’,’SIG_T2Y’,’SIG_T2Z’,’SIG_T2’,),
                   GROUP_MA=’PRES’,),
                   ),);
```
