# THER_LINEAIRE operator

## 1 Purpose

Solve a linear thermal problem, steady-state or transient.

The thermal load is defined by the keyword EXCIT.

The time discretization is given by the list of time steps defined under the keyword LIST_INST. This transient calculation can be initialized, at the first time step, in three different ways (keyword ETAT_INIT):

- by a constant temperature,
- by a temperature field, defined beforehand or extracted from a previous calculation,
- by a preliminary steady-state calculation.

The result object produced by this operator is of type evol_ther.

## 3 Operands

### 3.1 Operand RESULTAT

```text
◊  RESULTAT= mo
```

Name of the result object to enrich when a calculation is continued (see also ETAT_INIT).

### 3.2 Operand MODELE

```text
♦  MODELE = mo
```

Name of the model whose elements are the subject of the thermal calculation.

### 3.3 Operand CHAM_MATER

```text
♦  CHAM_MATER = chmat
```

Name of the material field assigned on the model.

### 3.4 Operand CARA_ELEM

```text
◊   CARA_ELEM = carac
```

The result object carac contains the properties of the thermal shell elements, if the model has any.

### 3.5 Keyword EXCIT

```text
♦  EXCIT =
```

Operand used to define several loads. For each occurrence of the factor keyword, one load is defined, possibly multiplied by a function of time.

#### 3.5.1 Operand CHARGE

```text
♦  CHARGE = char
```

Result object of type load produced by AFFE_CHAR_THER or by AFFE_CHAR_THER_F [U4.44.02]. As in mechanics, a load of the "imposed degree of freedom" kind, here the temperature, can also be defined with AFFE_CHAR_CINE [U4.44.03].

Important remark:

For each occurrence of the factor keyword EXCIT the various char result objects used must be built on the same model mo .

#### 3.5.2 Operand FONC_MULT

```text
◊  FONC_MULT = fonc
```

Multiplying coefficient, a function of time (result object of type fonction, nappe or formule), applied to the load.

Important remark:

Using FONC_MULT together with a load that contains temperature-dependent thermal loads is forbidden; that is, for loads of type ECHANGE_* .

#### 3.5.3 Operand TYPR_CALCUL

```text
◊   TYPE_CALCUL =      /   ‘TRAN’ ,               [ DEFAUT]
                        / ‘ STAT’ ,
```

<!-- page 4 -->

The calculation is transient if TYPE_CALCUL = 'TRAN' or steady-state if TYPE_CALCUL='STAT'. For a transient calculation, the calculation of the initial state must be specified.

### 3.6 Keyword ETAT_INIT

```text
SiTYPE_CALCUL = ‘TRAN’
   ♦  ETAT_INIT =
```

Defines the initial field from which the transient calculation is carried out.

#### 3.6.1 Operand STAT

```text
/  STAT = 'OUI'
```

The initial value of the temperature field is then the result of a preliminary steady-state calculation.

#### 3.6.2 Operand VALE

```text
/  VALE = tinit
```

The initial temperature is taken as constant over the whole structure.

#### 3.6.3 Operand CHAM_NO

```text
/  CHAM_NO = tinit
```

The initial value is defined by a temperature cham_no (result of the operator CREA_CHAMP [U4.72.04]).

#### 3.6.4 Operand EVOL_THER

```text
/  EVOL_THER = temp
```

The initial value is extracted from a data structure of type evol_ther.

#### 3.6.5 Operand NUME_ORDRE/INST

```text
◊  /NUME_ORDRE = nuini_evol
   /INST       = instini_evol
```

Step index of the field to extract from this data structure. The initial thermal state is extracted from the evol_ther_temp from the archiving index NUME_ORDRE or the archiving time step INST, to continue the calculation. If NUME_ORDRE or INST are not given, the last archived index that exists in evol is taken.

Remark:

Note that this is the step index in the data structure read back by the preceding keyword EVOL_THER. If this data structure was computed with a list of time steps different from the one used under the factor keyword INCREMENT of the current solution, NUME_ORDRE must be given under INCREMENT, since the same step index corresponds to different physical times. If the two lists of time steps are identical, the same NUME_ORDRE need not be given twice, under ETAT_INIT and under INCREMENT.

#### 3.6.6 Operand PRECISION/CRITERE

See [U4.71.00].

### 3.7 Keyword INCREMENT

```text
◊  INCREMENT =
```

Defines the calculation time steps that determine the time intervals used to integrate the differential equation.

The operands of the keyword INCREMENT have the same meaning as in the operator STAT_NON_LINE, see document [U4.51.03].

Remark:

If the keyword INCREMENT is absent, for a steady-state calculation a list of time steps reduced to the single real 0 is created.

### 3.8 Operand SCHEMA_TEMPS

This operand is available only for TYPE_CALCUL = 'TRAN'.

```text
◊  THETA = / theta,                 [R]
          /  0.57,                  [DEFAUT]
```

The argument theta is the parameter of the theta-method applied to the transient problem. It must lie between 0 (explicit method) and 1 (fully implicit method). If the keyword is absent, the value used is =0.57 , slightly above =0.5 which corresponds to the Crank- Nicholson scheme. The effect of the choice of theta on the stability of the method is detailed in [R5.02.02]. <!-- equation -->

### 3.9 Keyword SOLVEUR

```text
◊  SOLVEUR =
```

This factor keyword is optional: it defines the method for solving the linear systems. This operand is common to all the global commands [U4.50.01].

### 3.10 Keyword ARCHIVAGE

```text
◊  ARCHIVAGE =
```

This keyword is optional: by default, all the fields computed for all the computed steps are archived in the result object produced by the command. It is used to store only some step indices in a result data structure and/or to exclude some fields from storage.

This keyword is identical to its equivalent in the operator STAT_NON_LINE; see document [U4.51.03] for the description of the sub-keywords.

Remark:

If the calculation stops for lack of CPU time, the time steps computed before are saved in the database.

### 3.11 Operand TITRE

```text
◊  TITRE = titre
```

Title to give to the result temp stored in the data structure of type evol_ther [U4.03.01].

## 4 Modeling

Linear thermal problems can be handled with models that use the 3D, 2D, AXIS or COQUE finite elements described in documents [U3.22.01], [U3.23.01], [U3.23.02] and [U3.24.01].

## 5 Example

### 5.1 Transient calculation

```text
lr8=  DEFI_LIST_REEL   (  DEBUT = 0.E0 ,
                       INTERVALLE =(
                          _F(JUSQU_A   =   2.E-4 ,   NOMBRE=  2   ),
                          _F(JUSQU_A   =   1.E-3 ,   NOMBRE=  10  ),
                          _F(JUSQU_A   =   1.E-2 ,   NOMBRE=  9   ),
                          _F(JUSQU_A   =   1.E-1 ,   NOMBRE=  9   ),
                          _F(JUSQU_A   =   1.E+0 ,   NOMBRE=  9   ),
                          _F(JUSQU_A   =   2.0,  NOMBRE =  10 ),))
tempe = THER_LINEAIRE  (  MODELE    =  moth,
                       CHAM_MATER   =  chmat,
                       EXCIT        =  _F( CHARGE       =  chth),
                        TYPE_CALCUL  = ‘TRAN’,
                       ETAT_INIT =  _F(STAT   =  'OUI'),
                       INCREMENT =  _F(LIST_INST     =  lr8,
                                              NUME_INST_FIN=  30)
                       )
tempe = THER_LINEAIRE  (  reuse  =  tempe,
                        RESULTAT =  tempe,
                       MODELE    =  moth,
                       CHAM_MATER   =  chmat,
                       EXCIT        =  _F( CHARGE=   chth),
                       TYPE_CALCUL  = ‘TRAN’,
                       ETAT_INIT =  _F(EVOL_THER     =  tempe
                                              NUME_ORDRE      =   30),
                       INCREMENT =  _F(LIST_INST     =  lr8),
                       )
```

The first call to the command THER_LINEAIRE performs a steady-state calculation at time 0. and chains a transient calculation up to time 0.1 s (31 calculation time steps, that is 30 transient steps).

The second call enriches the preceding result object tempe; the transient calculation is continued from the 31st calculation time step.

## 6 Remark

The command CALC_CHAMP [U4.81.04] computes the heat fluxes, at Gauss points or at nodes, from the nodal temperature field obtained in this way by THER_LINEAIRE.
