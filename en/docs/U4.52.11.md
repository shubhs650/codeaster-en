# NORM_MODE operator

## 1 Purpose

The role of the command is to normalize mode shapes according to a criterion chosen by the user.

The modal analysis operator CALC_MODES [U4.52.02] produces a result object of type mode_meca or mode_meca_c whose real or complex mode shapes are normalized so that the largest component that is not a LAGRANGE multiplier is equal to 1.

The operator NORM_MODE lets the user choose another normalization method, for example generalized mass, generalized stiffness ...

Depending on the normalization chosen, the modal parameters (participation factor, effective mass, ...) are updated.

Reentrant operator.

<!-- page 2 -->

```text

          /  AVEC_CMP  =  a_cmp,                        [l_Kn]
      ◊   MODE_SIGNE   =  _F (
             ♦  GROUP_NO= grno,                      [group_no]
             ♦  NOM_CMP   =  cmp,                       [Kn]
             ◊  SIGNE  =  /  ‘POSITIF’,                 [DEFAUT]
                          /  ‘NEGATIF’,
                          )
      ◊   MASSE    =   masse ,                          [matr_asse_depl_r]
                                                     ou [matr_asse_gene_r]
                                                     ou [matr_asse_pres_r]
      ◊   RAIDE    =   masse ,                          [matr_asse_depl_r]
                                                     ou [matr_asse_depl_c]
                                                     ou [matr_asse_gene_r]
                                                     ou [matr_asse_pres_r]
```

## 3 Operands

### 3.1 Operand MODE

```text
♦  MODE = m_in
```

Name of the result object of type mode_* whose mode shape normalization is to be changed. If m_out is identical to m_in and the keyword 'reuse' is given with the value m_out, the renormalization is done in place.

### 3.2 Operand NORME

```text
◊ /NORME =
```

Symbolic name of the chosen norm.

```text
'MASS_GENE' :
```

The modes are normalized to unit generalized mass.

```text
'RIGI_GENE' :
```

The modes are normalized to unit generalized stiffness.

```text
'TRAN' :
```

The modes are normalized to 1. for the largest of the translation components: (components: DX, DY, DZ).

```text
'TRAN_ROTA' :
```

The modes are normalized to 1. for the largest of the translation and rotation components (components: DX, DY, DZ, DRX, DRY, DRZ).

```text
'EUCL' :
```

The modes are normalized to the Euclidean norm of the components that are not LAGRANGE multipliers (component: LAGR).

```text
'EUCL_TRAN' :
```

The modes are normalized to the Euclidean norm of the components that are translation components (components: DX, DY, DZ).

### 3.3 Operands GROUP_NO and NOM_CMP

```text
◊  GROUP_NO = grno
```

Name of the one-node group grno where the normalization is done. | Warning: the node group grno must contain a single node. ♦ NOM_CMP = cmp

Name of the normalization component at the node no or the one-node group grno . This operand is mandatory if GROUP_NO is given.

The modes are normalized to 1. for the component cmp of the node no or of the one-node group grno . <!-- equation -->

### 3.4 Operands AVEC_CMP / SANS_CMP

```text
◊  /  AVEC_CMP = a_cmp
```

a_cmp list of the names of the components used for the normalization.

<!-- page 4 -->

The modes are normalized to 1. for the largest of the components of the list a_cmp whatever the node.

```text
/  SANS_CMP = s_cmp
```

s_cmp list of the names of the components that are not used for the normalization. The modes are normalized to 1. for the largest of the components that is not in the list s_cmp.

### 3.5 Factor keyword MODE_SIGNE

This factor keyword imposes, for all the modes, the sign of a component of a node specified by the user. This factor keyword can only be used for real modes (generalized problem).

```text
♦    GROUP_NO = grnd
```

Name of the one-node group where the sign of a component is imposed. | Warning: the node group grnd must contain a single node. ♦ NOM_CMP = cmp

Name of the component of the one-node group grnd where the sign is imposed.

```text
◊     SIGNE =   / 'POSITIF'
                / 'NEGATIF'
```

Imposed sign of the component: 'POSITIF' or 'NEGATIF'.

### 3.6 Case of the normalization of a collection of modes coming from

```text
DEFI_BASE_MODALE
```

To normalize a collection of modes (modal basis) coming from DEFI_BASE_MODALE , the two matrices, mass and stiffness, used to update the modal parameters must be given:

```text
◊   MASSE    =   masse                  [matr_asse_depl_r]
                                 ou     [matr_asse_gene_r]
                                 ou     [matr_asse_pres_r]
◊   RAIDE    =   masse                  [matr_asse_depl_r]
                                 ou     [matr_asse_depl_c]
                                 ou     [matr_asse_gene_r]
                                 ou     [matr_asse_pres_r]
```

Indeed, in this case, the information on the mass and stiffness matrices (and possibly damping) on which the modal basis rests has been lost, or the modes may come from different sets of matrices. They must therefore be given again to the operator NORM_MODE.

For a basis of complex modes, a damping matrix must also be given to normalize with respect to the generalized mass or the generalized stiffness (see paragraph 4.2). ◊ AMOR = `masse` [matr_asse_depl_r] or [matr_asse_gene_r]

### 3.7 Operand TITRE

```text
◊  TITRE =   t
```

Title associated with the result object produced by this operator [U4.03.01].

### 3.8 Operand INFO

```text
◊  INFO = 1 ou 2
```

## 5 Updated modal parameters

A result object of type mode_meca can contain, for each mode, the following modal parameters (visible for example by printing the result object with the command IMPR_RESU in FORMAT='RESULTAT' with the option TOUT_PARA='OUI'):

| Name of the parameter in Code_Aster | Definition |
|---|---|
| FREQ | Natural frequency (damped, where applicable) |
| AMOR_GENE | Generalized modal damping |
| AMOR_REDUIT | Reduced modal damping |
| FACT_PARTICI_D* (* = X or Y or Z) | Participation factor of the mode in direction D* |
| MASS_EFFE_D* (* = X or Y or Z) | Effective modal mass in direction D* |
| MASS_EFFE_UN_D* (* = X or Y or Z) | Unit effective modal mass in direction D* |
| MASS_GENE | Generalized mass of the mode |
| OMEGA2 | Natural angular frequency (damped, where applicable) squared |
| RIGI_GENE | Generalized stiffness of the mode |

Table 5.1: list of the modal parameters.

These parameters are defined mathematically in the reference documentation [R5.01.03].

The operator NORM_MODE computes or updates the following modal parameters, which depend on the normalization chosen: FACT_PARTICI_D*, MASS_GENE and RIGI_GENE. It also enriches the data structure with the parameters MASS_EFFE_UN_D* (independent of the normalization). The other parameters are independent of the normalization.

## 6 Examples for real modes

For modes of type mode_meca (real mode shapes) coming from the solution of a generalized eigenvalue problem K−Mx=0 : <!-- equation -->

- normalizing an eigenvector x to unit generalized stiffness amounts to requiring that x satisfies

xTK x=1 <!-- equation -->

Normalization with duplication of the mode_meca result object:

```text
mo_2   = NORM_MODE (   MODE =mo_1,
                       NORME='RIGI_GENE'
                   );
```

- normalizing an eigenvector x to unit generalized mass amounts to requiring that x satisfies

xTM x=1 <!-- equation -->

Normalization to unit generalized mass, overwriting the mode_meca result object:

```text
mo  = NORM_MODE        (  reuse = mo,
                          MODE  = mo,
                          NORME = 'MASS_GENE'
                       );
```
