# FIN command

## 1 Purpose

This command ends the execution of a calculation cleanly. In this way, the memory manager is told that the objects can be released and written to disk in the global database (which allows a POURSUITE ).

Calling this procedure is mandatory for the execution to end correctly, which means that every command file must end with:

```text
FIN()
```

<!-- page 2 -->

## 2 Syntax

```text
FIN    (
          ◊  RETASSAGE =      /  'OUI',
                              /  'NON',              [DEFAUT]
          ◊  INFO_RESU =      /  'OUI',              [DEFAUT]
                              /  'NON'
          ◊  PROC0     =      /  'OUI',              [DEFAUT]
                              /  'NON'
        )
```

An exit argument is available for developers (see below)

<!-- page 3 -->

## 3 Operands

The FIN command saves all the objects computed during the execution in the file glob.1 (and possibly glob.2, ... if needed), as well as all the Python objects of the execution context in pickle files. These objects will be available for a POURSUITE of the calculation.

Note: Python objects of type class, function and type are not saved in pick.codeaster.objects.

When FIN has finished its work, Python goes on analyzing the instructions that follow, which will most likely fail if they use code_aster objects. The developer can use FIN(exit=True) to force the Python interpreter to quit.

### 3.1 Operand RETASSAGE

```text
◊  RETASSAGE =  /'OUI',
                /'NON',                 [DEFAUT]
```

Compacts the 'GLOBALE' database before it is written to the associated file. This keeps the databases smaller (rid of the objects associated with the objects destroyed by the user).

The command compacts the database as follows:

  - the databases are closed,
  - the 'GLOBALE' database is opened,
  - a 'VOLATILE' database is opened,
  - the 'GLOBALE' database is copied onto the 'VOLATILE' database, one non-empty record at a time,
  - the code renames this 'VOLATILE' database so that it is saved as if it were the usual 'GLOBALE' database. • The GLOBALE database is made of one or more binary files organized as fixed-length records. When objects are destroyed, the associated records are declared free and can be reused during the execution. At the end of the execution, unoccupied records may remain and add to the final size of the file. Compacting therefore reuses this space by reorganizing the records. It is an operation that can cause many disk reads and writes. In a parallel (MPI) execution, each instance of the GLOBALE database is processed, which multiplies the input/output.

### 3.2 Operand INFO_RESU

```text
◊  INFO_RESU =  /'OUI',                 [DEFAUT]
                /'NON',
```

Prints in the MESSAGE file information about the content of all the result data structures stored in the GLOBALE database.

Note:

Using this keyword can considerably increase the run time of the FIN command, so it is advisable to change the default value when running calculations that produce large amounts of data through their diversity.

<!-- page 4 -->

### 3.3 Operand PROC0

The operand PROC0, whose default value is 'OUI', restricts the writing of the data structures to the GLOBALE database to the processor of rank 0. If it is given the value 'NON', the save operations are done on all processors. This operation can be costly, so doing it on every processor can be very penalizing. It may be necessary to save on all processors when several command files (comm, com1, com2, etc...) are chained in the same execution.

This keyword only makes sense in parallel calculations and, except in particular cases, it works automatically. In distributed parallel mode (where each process sees only part of the model), all processes write ( PROC0='NON' ). In centralized parallel mode (classic parallelism), during the execution of the last command file, only process #0 writes the database. During the intermediate executions, all processes write.

#  -------------                -----------------
FIN( RETASSAGE='NON',
     INFO_RESU='OUI',
     PROC0='OUI',
   )
