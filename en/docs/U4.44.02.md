# AFFE_CHAR_THER and AFFE_CHAR_THER_F operators

## 1 Purpose

Assign thermal loads and boundary conditions on a model.

For the operator AFFE_CHAR_THER, the assigned values do not depend on any parameter and are defined by real values.

For the operator AFFE_CHAR_THER_F, the values are functions of one or more parameters chosen from the set (INST, X, Y, Z). For the loads used in nonlinear thermal analysis, the functions depend only on the temperature (TEMP) and must be tabulated. In addition, for some loads (for example SOURCE), the values can depend on the command variables.

These functions must first be defined by calling one of the operators:

- DEFI_CONSTANTE [U4.31.01] ;
- DEFI_FONCTION [U4.31.02] ;
- DEFI_NAPPE [U4.31.03] ;
- FORMULE [U4.31.0 5 ] ;
- CALC_FONC_INTERP [U4.32.01].

The result object produced is of type char_ther.

## 4 Operands

### 4.1 General remarks on the operands

#### 4.1.1 The two forms of operands under a factor keyword

The operands under a factor keyword are of two forms:

- the operands specifying the topological entities where the loads are assigned (keywords GROUP_NO and GROUP_MA, etc ...). The arguments of these operands are identical for the two operators.
- the operand or operands specifying the assigned values (TEMP, COEF_H, etc ...). The meaning of these operands is the same for the two operators, but their arguments are all of real type for the operator AFFE_CHAR_THER and of function type (created by one of the operators DEFI_FONCTION, DEFI_NAPPE, DEFI_CONSTANTE, FORMULE or CALC_FONC_INTERP) for the operator AFFE_CHAR_THER _F.

In this document we therefore do not distinguish the two operators AFFE_CHAR_THER and AFFE_CHAR_THER_F, unless expressly stated otherwise.

#### 4.1.2 Topological entities for assigning the loads

In general, the topological entities on which values must be assigned are defined:

- by nodes, with the operand GROUP_NO that takes a list of node groups,
- by element, with the operand GROUP_MA that takes a list of element groups,

Rule:

To define the assignment domain as simply as possible, the overwriting rule is used: the last assignment prevails.

### 4.3 Operand DOUBLE_LAGRANGE

```text
◊  DOUBLE_LAGRANGE = ’OUI’/’NON’
```

This keyword tells whether or not the user wants to double the Lagrange multipliers used to enforce the boundary conditions in the assembled matrix. In practice, doubling the Lagrange multipliers allows linear solvers that do not pivot to be used. Not doubling the Lagrange multipliers reduces the number of degrees of freedom of the problem (and therefore the size of the problem to solve), but its use is limited to the solvers MUMPS and Petsc.

<!-- page 8 -->

Note that the two Lagrange multipliers associated with the relation are placed so that, in the assembled matrix, the first is before all the terms involved in the relation and the second after. This choice has the advantage of giving an assembled matrix with a smaller footprint, but the disadvantage that a singularity can appear in the matrix. Since the numbering may in any case be changed by the renumbering tool of the chosen external solver, this detail remains purely technical.

### 4.10 Keyword PRE_GRAD_TEMP

#### 4.10.1 Purpose

Factor keyword used to apply to a 3D or 2D (PLAN, AXIS) element a temperature gradient assumed uniform in the element. This "initial" temperature gradient can be used for example to solve the element problems that determine the correctors of steady linear thermal analysis in the periodic base domain («cellule de base») (2D, 3D), in periodic homogenization.

The homogenized conductivity coefficients are obtained by computing, with the operator POST_ELEM [U4.81.22] keyword ENER_POT, the energy dissipated thermally at equilibrium in linear thermal analysis from the correctors.

Because of the thermal analogy, this approach can be used to obtain the correctors in antiplane elasticity in the 2D base domain, as well as in electrical conduction.

The calculation uses the conductivity of the material. It is assumed to be isotropic and independent of the temperature.

The assignment can be made on one or more elements or on all the elements of the model.

#### 4.10.2 Syntax

```text
•  pourAFFE_CHAR_THER
   PRE_GRAD_TEMP = _F  (
                   ♦   /  TOUT     =       'OUI',
                       /  GROUP_MA =       lgma,           [l_gr_maille]
                   ♦   |  FLUX_X =         flx,               [R]
                       |  FLUX_Y =         fly,               [R]
                       |  FLUX_Z =         flz,               [R]
                       )
```

#### 4.10.3 Operands

This load applies to the following element types and modeling types:

Element Modeling type

```text

          QUAD4, QUAD8, QUAD9       PLAN_DIAG, AXIS_DIAG
            HEXA8, HEXA20,
                HEXA27
                                         3D, 3D_DIAG

            TETRA4, TETRA10
             PYRA5, PYRA13
♦  |  FLUX_X = flx (flxf)
   |  FLUX_Y = fly (flyf)
   |  FLUX_Z = flz (flzf) (en 3D seulement)
```
