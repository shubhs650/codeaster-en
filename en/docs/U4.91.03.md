# IMPR_TABLE procedure

## 1 Purpose

Print the content of a table to a file.

The command prints a subset of the table in different formats. The default format (TABLEAU) is handy for post-processing with spreadsheet-type software; other formats can be viewed directly with a curve plotter (for example xmgrace).

## 3 Operands

### 3.1 What is a table?

A table is a computer data structure that stores a set of integer, real, complex or character-string values.

A table is like a spreadsheet: it can be seen as a list of columns side by side. Each column has a field name, which we call a parameter, and holds similar data of type: I, R, C, K8, K16, K24 or K32.

Example:

| NUME_ORDRE | INST | NOEUD | G |
|---|---|---|---|
| 1 | 10. | N1 | 5. |
| 1 | 10. | N2 | 6. |
| 1 | 10. | N3 | 7. |
| 1 | 10. | N4 | 8. |
| 2 | 20. | N1 | 9. |
| 2 | 20. | N2 | 9. |
| 2 | 20. | N3 | 8. |
| 2 | 20. | N4 | 8. |
| 3 | 30. | N1 | 7. |
| 3 | 30. | N2 | 6. |
| 3 | 30. | N3 | 5. |

A table can also be seen as a sequence of records (which we call rows). The rows do not all have the same structure (that is, the same parameters). For example:

| ACTION | NUME_ORDRE | INST | NOEUD | DX | DY | MAILLE | SIXX |
|---|---|---|---|---|---|---|---|
| INTITULE 1 | 1 | 10. | N1 | 3. | 5. |   |   |
| INTITULE 1 | 1 | 10. | N2 | 6. | 7. |   |   |
| INTITULE 1 | 1 | 10. | N3 | 8. | 9. |   |   |
| INTITULE 1 | 2 | 20. | N1 | 11. | 12. |   |   |
| INTITULE 1 | 2 | 20. | N2 | 15. | 13. |   |   |
| INTITULE 1 | 2 | 20. | N3 | 19. | 18. |   |   |
| INTITULE 2 | 2 | 20. |   |   |   | MA1 | -12. |
| INTITULE 2 | 2 | 20. |   |   |   | MA2 | -14. |

To print the content of a table, the user can:

- select the columns and rows to print [§3.6]
- choose a sort order for the rows printed [§3.7]
- choose the print "format": in rows, in arrays, ... [§3.8]

### 3.2 Operand TABLE

```text
♦  TABLE = matable
```

Name of the table to print

### 3.3 Operand TITRE

```text
◊  TITRE = titre
```

Character string printed before the table (and before any title attached to the table). It helps tell apart tables printed one after the other in the same file.

<!-- page 5 -->

### 3.4 Selecting what to print: the keywords FILTRE and

```text
NOM_PARA,TOUT_PARA
```

The user chooses the columns to print with the keywords NOM_PARA and TOUT_PARA, and the rows to print with the factor keyword FILTRE (repeatable at will).

#### 3.4.1 Keyword FILTRE

The factor keyword FILTRE keeps only the rows of the table that meet criteria set by the user. The occurrences of the keyword add up as successive filters (« AND » filters). Each occurrence gives the name of the parameter the condition applies to, the type of condition (equality, non-equality, less than, ...) and the value associated with the condition.

##### 3.4.1.1 Operand NOM_PARA

```text
◊  NOM_PARA = para
```

para is the name of the parameter the filter condition applies to.

##### 3.4.1.2 Operand CRIT_COMP

```text
◊  CRIT_COMP = crit
```

crit is the type of the filter condition.

| EQ | "equality" for integers, texts, reals or complexes. For floating-point numbers (real or complex), equality is evaluated with a tolerance given by the keywords PRECISION and CRITERE. |
|---|---|
| NE | "non-equality" (see EQ) |
| LT | "less than". Order relations: - natural for integers and reals - alphabetical for texts - invalid for complexes |
| GT | "greater than" (see LT) |
| LE | "less than or equal to" (see LT) |
| GE | "greater than or equal to" (see LT) |
| VIDE | empty entry |
| NON_VIDE | non-empty entry |
| MAXI | the row kept is the one with the largest value |
| MAXI_ABS | the row kept is the one with the largest absolute value |
| MINI | the row kept is the one with the smallest value |
| MINI_ABS | the row kept is the one with the smallest absolute value |
| REGEXP | matches the regular expression given by VALE_K |

Warning: in the extraction commands EXTR_TABLE/RECU_FONCTION, the criteria MINI/MAXI (and MINI_ABS/MAXI_ABS) select a single row that meets the criterion, the last one, whereas in the commands that handle tables, CALC_TABLE/IMPR_TABLE, all the rows that meet these criteria are kept. The regular-expression filter is available only in CALC_TABLE.

##### 3.4.1.3 Operands VALE / VALE_I / VALE_C / VALE_K

These keywords are used according to the type of the column of the parameter the condition applies to: integer, real, complex or text.

The argument is the value associated with the condition; for example 12 to keep only step index 12. Several values can be given (for equality or inequality tests) to apply an « OR » filter (see the example below).

<!-- page 6 -->

This operand is not needed with the condition types 'VIDE', 'NON_VIDE', 'MAXI', 'MINI', …

VALE_K is also used to give the regular expression to match (CRIT_COMP='REGEXP'). Example: VALE_K='^N[MP]' keeps only the rows where, for the chosen parameter, the entry holds a character string that starts with an N (capital) followed by an M or P, then possibly other characters (see the Python module re for more details on regular expressions).

##### 3.4.1.4 Operands CRITERE / PRECISION

When the constrained parameter is a floating-point type (real or complex) and the condition is equality (or non-equality), equality is evaluated with a tolerance.

PRECISION = eps, eps is the tolerance

```text
CRITERE=  /'RELATIF' ,    |x-xref| < eps*|xref|
          /'ABSOLU'  ,    |x-xref| < eps
```

##### 3.4.1.5 Example of the keyword FILTRE

Given:

```text
FILTRE= ( _F(NOM_PARA= 'NOEUD', VALE_K  = ('N7', 'N12'),),
          _F(NOM_PARA= 'INST' , CRIT_COMP= 'GT' , VALE= 3.0,),
          _F(NOM_PARA= 'INST' , CRIT_COMP= 'LT' , VALE= 13.0,),
        ),
```

this selects the rows of the table where the parameter NOEUD is 'N7' or 'N12' and the parameter INST is between 3. and 13.

#### 3.4.2 Operand NOM_PARA

If the keyword NOM_PARA is absent, all the columns of the table are printed.

<!-- chunk 3 fr=731bb0f6b7a6 method=machine source=session:task-5.2 on=2026-10-30 -->

If the user gives the keyword NOM_PARA = lpara, only the parameters in the list lpara are printed, in the order of the list.

### 3.5 Sorting the rows of a table: the factor keyword TRI

Only one occurrence of the factor keyword TRI is accepted.

#### 3.5.1 Operand NOM_PARA = lpara

This keyword gives the list of parameters used to sort the rows of the table (several parameters may be needed). When two rows tie on the first parameter, the next one is used …

Note:

Parameters that are not printed can be used for sorting.

#### 3.5.2 Operand ORDRE

This keyword says whether to sort in increasing or decreasing order. By default, rows are sorted in increasing order.

The order relations used are:

- the natural order for integers and reals,
- the alphabetical order for texts and object names.

Notes:

<!-- page 7 -->

A complex parameter cannot be used to sort the rows of a table.

For parameters of type NOEUD (or MAILLE ), the order is alphabetical, because these parameters hold the names of the nodes (or elements).

#### 3.5.3 Example of the keyword TRI

Given:

```text
TRI=_F (NOM_PARA= ('NOEUD','INST'), ORDRE= 'CROISSANT'),
```

the rows of the table are printed in the alphabetical order of the nodes. If several rows belong to a given node, the second sort criterion (INST) orders them.

### 3.6 Choice of the print format: keywords FORMAT, PAGINATION, ...

The default print format is ‘TABLEAU’, that is the selected parameters laid out in columns (as in the examples of this document). The software EXCELTM offers a set of tools to work with this kind of file: sorting, filtering, pivot tables, ...

#### 3.6.1 FORMAT = ‘TABLEAU’ or ‘AGRAF’

An example of a table printed in the ‘TABLEAU’ format:

```text
NUME_ORDRE   INST   NOEUD  DX   DY
     1       4.     N7     3.4  3.8
     1       4.     N4     2.4  2.8
     1       4.     N2     1.4  1.8
     4       8.     N7     3.4  3.8
     4       8.     N4     2.4  2.8
     4       8.     N2     1.4  1.8
     7       20.    N7     3.4  3.8
     7       20.    N4     2.4  2.8
     7       20.    N2     1.4  1.8
```

The only difference between the ‘TABLEAU’ format and the ‘AGRAF’ format is that in the latter the "text" columns (for example NOEUD above) are preceded by a "\".

Note:

In the AGRAF format, no directives (.digr file) are produced, only the values (.dogr file).

#### 3.6.2 Layout in the TABLEAU format

The look of the printed table is set here: from a classic table in columns to a csv- or html-compatible format…

```text
◊  DEBUT_TABLE = texte
```

Text printed before each table (by default, a line of dashes).

```text
◊  FIN_TABLE = texte
```

Text printed after each table (nothing by default).

```text
◊  SEPARATEUR = separ
```

Separator between two columns (a space by default).

```text
◊  COMMENTAIRE = com
```

Character inserted at the start of a line to mark it as a comment (or title; # by default).

<!-- page 8 -->

```text
COMM_PARA = comp
```

Character inserted to comment out the line of labels (by default, no character is inserted).

```text
◊  DEBUT_LIGNE = deb
```

String inserted at the start of each line (empty by default).

```text
◊  FIN_LIGNE = fin
```

String inserted at the end of each line ('\n' by default).

#### 3.6.3 FORMAT = ‘ASTER’

The difference between the ‘ASTER’ format and the ‘TABLEAU’ format is the header of the table and its last line. The difference exists because a table printed in the ‘ASTER’ format can be read back by Code_Aster (command LIRE_TABLE [U7.02.03]).

Example:

```text
       #DEBUT_TABLE
       #TITRE ASTER  6.03.11 CONCEPT TAB_REAC CALCULE LE 12/07/2002
       #TITRE TABL_POST_RELE
        INTITULE   RESU    NOM_CHAM      NUME_ORD    INST         DY
        K8         K8      K16           I           R            R
        MESSAGE    RESU    REAC_NODA              1  2.50000E-01 -2.25146E+00
        MESSAGE    RESU    REAC_NODA              2  5.00000E-01 -4.44089E+00
        MESSAGE    RESU    REAC_NODA              3  7.50000E-01 -6.59515E+00
        MESSAGE    RESU    REAC_NODA              4  1.00000E+00 -8.65972E+00
        MESSAGE    RESU    REAC_NODA              5  1.25000E+00 -1.06742E+01
        MESSAGE    RESU    REAC_NODA              6  1.50000E+00 -1.26438E+01
        MESSAGE    RESU    REAC_NODA              7  1.75000E+00 -1.45569E+01
       #FIN_TABLE
3.6.4 FORMAT='NUMPY'
```

Numpy is a Python module for handling arrays. Printing in this format produces a file that the function numpy.load() can read back. Only the real and integer parameters (columns) are printed (integers are converted to reals automatically). The other parameters are ignored. The layout of the table is kept: the result is a numpy array with as many rows as the table and as many columns as there are real or integer parameters.

Note: for a parametric calculation, a single row is expected in the printed array. Use CALC_TABLE to filter the rows if needed.

#### 3.6.5 FORMAT = ‘TABLEAU_CROISE’

The 'TABLEAU_CROISE' format is for two-way tables. The table is printed as an array with labeled column names and row names. This printout applies to tables with 3 parameters: the values of one of the 3 parameters are shown as a function of the 2 others.

Example: DX as a function of NOEUD and INST:

```text
DX FONCTION DE NOEUD ET DE INST     4.      8.   20.
NOEUD/INST                       N7 3.4     3.4  3.4
                                 N4 2.4     2.4  2.4
                                 N2 1.4     1.4  1.4
NOM_PARA = ('INST', 'NOEUD',  'DX')
```

<!-- page 9 -->

The parameter that "fills" the array is the 3rd of the list given by the simple keyword NOM_PARA. The "abscissa" parameter is the 2nd of that list. The "ordinate" parameter is the 1st of that list.

<!-- chunk 4 fr=0e73237c4acf method=machine source=session:task-5.2 on=2026-10-30 -->

Note:

If the table has more than 3 parameters, the keyword PAGINATION can be used to "step through" the values taken by the other parameters (see example 3).

#### 3.6.6 FORMAT = ‘XMGRACE’

This format produces a file that xmgrace can show directly as a curve. The same layout features as in IMPR_FONCTION are available.

If PILOTE is not given, a data file for xmgrace is produced; if PILOTE is given and the chosen driver is available on the machine, a postscript, png, … file can be produced directly.

Keywords for the layout of the graph: see IMPR_FONCTION [U4.33.01].

#### 3.6.7 Operand PAGINATION

This keyword prints a table in pieces (as a set of smaller tables). It takes a list of parameters (lpagi) whose values are stepped through and printed as the titles of the small tables.

The list of pagination parameters (lpagi) must be included in the full list of parameters to print (lpara).

To combine pagination with the 'TABLEAU_CROISE' format, the list lpara, once the parameters of lpagi are removed, must leave 3 parameters. These 3 parameters are used for the array layout [§3.4.3].

```text
 Exemple:FORMAT=‘TABLEAU’, PAGINATION = ‘NOEUD’
 NOEUD: N7
 NUME_ORDRE   INST    DX     DY
 1            4.      3.4    3.8
 4            8.      3.4    3.8
 7            20.     3.4    3.8
NOEUD: N4
 NUME_ORDRE   INST    DX     DY
 1            4.      2.4    2.8
 4            8.      2.4    2.8
 7            20.     2.4    2.8
NOEUD: N2
 NUME_ORDRE   INST    DX     DY
 1            4.      1.4    1.8
 4            8       1.4    1.8
 7            20.     1.4    1.8
```

#### 3.6.8 Operand FORMAT_C

For complex numbers, two print formats are available (modulus/phase by default, or real part/imaginary part).

<!-- page 10 -->

#### 3.6.9 Operand FORMAT_R

This keyword chooses the number of decimals printed for each floating-point number (real or complex).

It uses the FORTRAN syntax.

For example, with the default value 'E12.5', each floating-point number is printed on 12 characters, with 5 decimals, in scientific notation (with an exponent).

#### 3.6.10 Operand IMPR_FONCTION

For tables whose entries hold function names, this keyword says that the content of the functions referenced in the table is printed too.

The table is printed first (as described above), then the code "loops" over all the functions in the printed part of the table and prints them (as the command IMPR_FONCTION does).

## 4 Examples

Example 1: to discover the structure of a table

```text
IMPR_TABLE(TABLE = POST_REL)
```

Example 2: print a few parameters with a filter and sorting

```text
IMPR_TABLE(TABLE = POST_REL,
   FILTRE=_F(NOM_PARA='INST', VALE= 0.,    CRITERE = 'ABSOLU'),
   TRI=_F(NOM_PARA=('ABSC_CURV ', 'COOR_X'),ORDRE=('CROISSANT'),
   NOM_PARA = ( 'COOR_X', 'TEMP'),
)
```

Example 3: use pagination and the TABLEAU_CROISE format

```text
IMPR_TABLE(TABLE = POST_REL,
   NOM_PARA = ( 'COOR_X', 'TEMP', 'ABSC_CURV', 'INST', 'COOR_Y'),
   PAGINATION= ('INST ', 'COOR_X'),
   FORMAT = 'TABLEAU_CROISE',
)
```

### 4.1 Operand UNITE

Chooses the file the table is printed to. By default, the table is printed to the file associated with logical unit 8. In the 'XMGRACE' format, the default value is 29, type dat in astk.
