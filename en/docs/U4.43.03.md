# AFFE_MATERIAU operator

## 1 Purpose

Assign materials to geometric zones of a mesh or a model. There can be up to 26 materials on the same element (which is needed for multifiber beams or polycrystalline materials), but only one field of type cham_mater can be used in the operators.

Define the external state variables (temperature, space, hydration, drying, corrosion,…) for the numerical calculations.

Produces a data structure of type cham_mater.

<!-- page 2 -->

## 3 General

This command assigns the material properties to the finite elements of the model (even though it is the elements of the mesh that are actually assigned). These material properties are defined in the materials assigned to the elements (keyword MATER). Each material holds a number of parameters (Young's modulus, density, ...). These parameters can be functions of some variables. We call these variables "external state variables".

The external state variables currently used are:

- temperature,
- space,
- hydration,
- drying,
- metallurgical phases,
- irradiation,
- corrosion,
- …

All these external state variables must be assigned with the command AFFE_MATERIAU (keyword AFFE_VARC).

For models with multifiber beams, the "behaviors" defined with the command DEFI_COMPOR/MULTI_FIBRE [U4.43.06] must also be assigned in this command.

## 4 Operands

```text
4.1  MAILLAGE
          MAILLAGE = ma,
```

Name of the mesh (or skeleton) to which material properties are assigned.

Notes:

  - The assignment works the same for the elements of a skeleton as for the elements of a mesh. In the rest of this document, we always say mesh for simplicity. •
  - Materials are assigned to the elements of a skeleton when stresses (for example) are to be computed on the (coarser) post-processing elements.

```text
4.2  MODELE
          MODELE = mo,
```

Name of the model. If this argument is used, the code checks that the elements assigned in the command belong to the model.

### 4.3 Factor keyword AFFE

The factor keyword AFFE assigns different materials to "pieces" of the mesh.

#### 4.3.1 Note on fracture mechanics calculations

As a rule, the material properties must be known on the finite elements that model the "material": the "volume" (or structural) elements. The "skin" finite elements are there to apply boundary conditions and do not need the material properties of the underlying material. There is one exception, for the option CALC_K_G of the operators CALC_G_XXXX. For these calculations, the finite elements that model the crack lips must be assigned the same material as the underlying "volume" elements.

<!-- page 5 -->

#### 4.3.2 Operands TOUT='OUI', GROUP_MA

The keywords TOUT and GROUP_MA designate the set of elements assigned.

If an element appears in several occurrences of the factor keyword AFFE, the overwrite rule applies: the last assignment wins [U2.01.08].

#### 4.3.3 Operand MATER

```text
♦  MATER = mat,
```

Name of the material to assign.

In general, each element is assigned only one material. Sometimes a list of materials must be given, when the nonlinear mechanical behavior is obtained with the command DEFI_COMPOR [U4.43.06]. In that case, the list is limited to 26 materials.

Warning: even if there can be several materials per element, only one field of type cham_mater can be used in the operators.

### 4.4 Keyword AFFE_VARC

This factor keyword assigns fields of external state variables to the elements of the mesh. It can be repeated. Several occurrences of AFFE_VARC are needed to assign several different external state variables, but several occurrences can also be used for a single variable. For example, on a mixed model (3D + beams), the temperature can be assigned as: 1 evol_ther computed on the 3D elements 1 temperature field (constant in time) on the beam elements.

An external state variable is a (real) scalar that can affect the material behavior through the parameters that are functions (for example a parameter of DEFI_MATERIAU / ELAS_FO). An external state variable is a field known before the calculation. This field can vary in time. In rare cases, external state variables can be used as variables of a function that defines a load (e.g. AFFE_CHAR_THER_F/SOURCE).

External state variables were introduced above all for mechanical calculations. The most common external state variable for mechanical calculations is the temperature.

For thermal calculations, one (or more) external state variables can be used, but only for a very few parameters:

```text
SECH_NAPPE      / FONCTION
THER_FO         / LAMBDA
THER_FO         / RHO_CP
THER_COQUE_FO   / COND_LMM, COND_TMM, ...
```

Also for thermal calculations, external state variables can be used among the variables of the functions given to the following command:

```text
AFFE_CHAR_THER_F/SOURCE
```

<!-- page 6 -->

#### 4.4.1 Operand NOM_VARC

```text
♦  NOM_VARC = nomvarc,
```

Name of the external state variable to assign (TEMP, GEOM, IRRA, CORR, HYDR, SECH, ...).

Meaning and role of the different variables:

| TEMP | temperature |
|---|---|
| GEOM | space directions |
| CORR | corrosion of steels |
| EPSA | anelastic strain |
| HYDR | hydration of concrete |
| IRRA | Irradiation |
| M_ACIER | metallurgical phases of steel |
| M_ZIRC | metallurgical phases of zircaloy |
| NEUT1 | « neutral » variable 1: makes the material coefficients vary with a "user" parameter (see example 3 below) |
| NEUT2 | « neutral » variable 2 (like NEUT1) |
| NEUT3 | « neutral » variable 3 (like NEUT1) |
| SECH | drying of concrete |
| PTOT | Total fluid pressure in THM (chained solution) |
| DIVU | Volumetric strain in THM (chained solution) |

Some external state variables are scalars. Others are "vectors" with several scalar components. The table below gives the names of the components of the external state variables

| TEMP | TEMP, TEMP_MIL, TEMP_SUP, TEMP_INF |
|---|---|
| GEOM | X, Y, Z |
| CORR | CORR |
| EPSA | EPSAXX, EPSAYY,EPSAZZ, EPSAXY,EPSAXZ, EPSAYZ |
| HYDR | HYDR |
| IRRA | IRRA |
| M_ACIER | FERRITE, PPERLITE, PBAINITE, PMARTENS, PAUSTENI, PCOLDSUM, TAUSTE, TRANSF, TACIER |
| M_ZIRC | ALPHPUR, ALPHBETA, BETA, TZIRC, TEMPS |
| NEUT1 | NEUT1 |
| NEUT2 | NEUT2 |
| NEUT3 | NEUT3 |
| SECH | SECH |
| PTOT | PTOT |
| DIVU | DIVU |

The external state variable IRRA is a fluence, that is the time integral of a neutron flux. It is used by several constitutive laws, in specific units:

- it must be given in DPA (displacements per atom) for the law IRRAD3M (cf. [R5.03.23]);
- it must be given in 1020n/cm2 for the laws VISC_IRRA_LOG, GRAN_IRRA_LOG, LEMAITRE_IRRA (cf. [R5.03.09]).

#### 4.4.2 Operands TOUT='OUI', GROUP_MA

These keywords designate the elements of the zone to assign.

<!-- page 7 -->

#### 4.4.3 Operand CHAM_GD

This keyword associates the field chvarc with the external state variable nomvarc. This field is a field of reals (not functions). It is therefore independent of time and is used throughout transient calculations. If the values of the external state variable depend on time, use the keyword EVOL (see below). ELGA cham_elem are allowed only if they come from the operator PROJ_CHAMP/ METHODE = 'SOUS_POINT', to assign the values at the Gauss sub-points of elements with sub-points.

#### 4.4.4 Operands EVOL, NOM_CHAM, FONC_INST, PROL_DROITE, PROL_GAUCHE

These keywords associate the transient evovarc with the external state variable nomvarc. The keyword NOM_CHAM gives the symbolic name of the fields of the result data structure to use. By default, the code chooses:

| NOM_VARC | NOM_CHAM |
|---|---|
| TEMP | 'TEMP' |
| GEOM | 'GEOM' |
| CORR | 'CORR' |
| EPSA | 'EPSA_ELNO' |
| HYDR | 'HYDR_ELNO' |
| IRRA | 'IRRA' |
| M_ACIER | 'META_ELNO' |
| M_ZIRC | 'META_ELNO' |
| NEUT1 | 'NEUT' |
| NEUT2 | 'NEUT' |
| NEUT3 | 'NEUT' |
| SECH | 'TEMP' |
| PTOT | 'DEPL' |
| DIVU | 'EPSI' |

The fields are real fields (neither complex nor functions). ELGA cham_elem are allowed only if they come from the operator PROJ_CHAMP/ METHODE = 'SOUS_POINT', to assign the values at the Gauss sub-points of elements with sub-points.

The keyword FONC_INST = finst defines a function (of time) that maps the "time" of the evolution evovarc (t_evo) to the "time" of the later calculation (t_calc). The function can be a simple "shift" (to account for the mechanical calculation starting at a time different from the start of the thermal calculation), but it can be more complex, for example to impose a "cyclic" mechanical load (thermal expansion) while computing only one temperature cycle. See the test case zzzz223a for an illustration of this keyword.

Warning: the function finst is the one that transforms t_calc into t_evo: t_evo = finst(t_calc)

<!-- chunk 4 fr=78b7739feda2 method=machine source=session:task-5.2 on=2026-10-30 -->

The keywords PROL_GAUCHE and PROL_DROITE say whether the transient evovarc can be used before its "min" time (PROL_GAUCHE) and/or after its "max" time (PROL_DROITE). The value 'EXCLU' raises an error if the transient is used outside its domain. The value 'CONSTANT' extends the transient with the values at the "min" (or "max") time. The value 'LINEAIRE' extends the transient linearly from its first (or last) 2 points.

#### 4.4.5 Operand VALE_REF

This keyword defines a "reference" value for the external state variable nomvarc when it needs one. Currently, only two external state variables need a reference value: 'TEMP' and 'SECH'. For these two variables, the keyword VALE_REF is mandatory. For the other variables, it is forbidden. For the external state variable 'TEMP' on shells, the reference temperature is assumed to be the same for the 3 components, which is why it is entered only once.

```text
♦  VALE_REF = Tref (ou c0)       [R]
```

##### 4.4.5.1 Reference temperature ( T ) : ref

The reference temperature T given after the keyword VALE_REF is the temperature ref at which there is no thermal strain (cf. [R4.08.01]). <!-- equation -->

If the thermal expansion coefficient  (whose value is given in the command DEFI_MATERIAU [U4.43.01]) does not depend on temperature: thT=T−T . ref <!-- equation -->

If the thermal expansion coefficient depends on temperature, the mathematical expression of the thermal strain depends on how the thermal expansion coefficient is given in the command DEFI_MATERIAU:

  - the values of the thermal expansion coefficient (given in DEFI_MATERIAU) were determined by dilatometry tests made at the temperature T . ref In this case, the keyword TEMP_DEF_ALPHA must not be given in the command DEFI_MATERIAU and the thermal strain is computed by the expression:

thT=TT−T , thT =0 ref ref <!-- equation -->

where T is given under the keyword ALPHA (or ALPHA_*) in DEFI_MATERIAU. <!-- equation -->

  - the values of the thermal expansion coefficient were determined by dilatometry tests made at a temperature T different from the def reference temperature T . ref A change of reference must then be made in the calculation of the thermal strain [R4.08.01]. thT=thT−thT  m m ref

where th is the measured thermal strain (defined with respect to the temperature m T ), def th is the computed thermal strain (defined with respect to the temperature T ). ref <!-- equation -->

The temperature T is given under the keyword TEMP_DEF_ALPHA in def DEFI_MATERIAU, and the values of the expansion coefficient (defined with respect to the temperature T ) are given under the keyword ALPHA or (ALPHA_*) in def <!-- equation -->

```text
DEFI_MATERIAU.
```

Note:

  - In a THM modeling, temperature is not an external state variable and the expansion coefficient cannot be a function of temperature. So do not use the external state variable TEMP in THM. An error message will stop you
<!-- page 9 -->

  - A formula or a two-variable function cannot be used for ALPHA, because of the changes described above. The parameter ALPHA can depend ONLY on temperature, and only if it is a function. To use a formula, first tabulate it with the command CALC_FONC_INTERP .

##### 4.4.5.2 Reference drying ( c ) : 0

c is the initial water content of the concrete. The user must give this number when running 0 a mechanical calculation (MECA_STATIQUE or STAT_NON_LINE) with a load of the drying type. <!-- equation -->

c0 must be given in the same units as the "drying" (AFFE_MATERIAU/AFFE_VARC= _F(NOM_VARC='SECH' ...), for example in L/m3). This unit must be consistent with the parameter DEFI_MATERIAU/ELAS_FO/K_DESSIC.

At this initial water content, the drying shrinkage is zero since:

```text
EPS_rd = K_DESSIC(c0 - c).
```

#### 4.4.6 Initial state in STAT_NON_LINE

In the command STAT_NON_LINE, the initial state is not computed; the user gives it. By default, the initial state of a calculation is « virgin »: displacements, stresses and internal variables are zero.

An inconsistent initial state may disappear from the first computed time step, but it may also persist. This depends on how the constitutive law is integrated (the choice of whoever programmed the law).

If the behavior is integrated incrementally (old wording: COMP_INCR), the inconsistency of the initial state persists at all times of the calculation. Otherwise, it disappears at the first time step.

So it is very important that the initial state of the calculation be « right ».

If the external state variables at the initial time cause nonzero anelastic strains, this strain makes the initial state incorrect. Indeed, one must have:

σ=A(ϵ−ϵ ) anel Since the displacement is zero, the strain ϵ is zero. The stress σ cannot be zero. <!-- equation -->

In practice, at the initial time:

- the temperature must equal the reference temperature
- the hydration must be zero
- …

#### 4.4.7 « Hidden » keywords for assigning external state variables

We have seen how the user can assign fields (standalone or from a `sd_resultat`) as external state variables for later calculations. But external state variables are named scalars and the associated fields also have named components. The problem is to associate each external state variable with a component of the field.

There are as many « hidden » factor keywords as external state variables to make these associations. These keywords are « hidden » because they have default values (see the table below). Use them only to do something a little « special ». For example:

<!-- page 10 -->

- use the variables NEUT_1 or NEUT_2,
- pass a temperature field off as a corrosion field,
- …

These factor keywords are explained with two examples:

The user ran a « thermal » calculation whose solution is in fact an evolution evo1 whose fields hold drying. In this evol_ther, the fields called TEMP carry a component also called TEMP.

To use such fields as the external state variable SECH, the user can write:

```text
CHMAT=AFFE_MATERIAU(...
      VAR_SECH=_F(NOM_VARC='SECH', GRANDEUR='TEMP_R',
                                         CMP_VARC='SECH', CMP_GD='TEMP'))
```

which reads: « the fields I want to assign as the external state variable 'SECH' are of the quantity TEMP_R and the component to use is 'TEMP'.

When an external state variable is a « vector » with several scalar components, for example the variable M_ACIER, which has 9 components ('PFERRITE',...,'TACIER'), the user can write:

```text
CHMAT=AFFE_MATERIAU(...
       VAR_M_ACIER=_F( NOM_VARC='M_ACIER', GRANDEUR='VARI_R',
                      CMP_VARC=('PFERRITE', 'PPERLITE', …, 'TACIER'),
                      CMP_GD=('V1', 'V2', …, 'V9'')))
```

which means: « the fields I want to assign as the external state variable 'M_ACIER' are of the quantity VARI_R and the correspondence of the components to use is:

```text

```

### 4.5 Factor keyword AFFE_COMPOR

This factor keyword assigns the "multifiber behavior" of multifiber beam elements.

The keywords TOUT and GROUP_MA designate the set of elements assigned.

After the keyword COMPOR, the user gives the name of an object of type compor from the command DEFI_COMPOR/MULTIFIBRE.

#### 4.5.1 Operand MATER

```text
♦  MATER = mat,
```

Name of the material to assign.

In general, each element is assigned only one material. Sometimes a list of materials must be given, when the nonlinear mechanical behavior is obtained with the command DEFI_COMPOR [U4.43.06].

## 5 Examples

Example 1: mechanics without thermal expansion

```text
chmat = AFFE_MATERIAU  (  MAILLAGE = ma,
        AFFE = (
          _F(TOUT = 'OUI' ,                MATER = acier),
          _F(GROUP_MA=('gma1','gma2','gma3'), MATER = alu,),),
                       )
```

<!-- page 12 -->

The material named `acier` is assigned to the whole mesh (except the elements in the groups gma1, gma2, gma3). The material `alu` is assigned to the elements in the groups gma1, gma2, gma3.

Example 2: mechanics with thermal expansion

The material MAT, some of whose parameters are functions of temperature, is assigned to the whole mesh. The thermal expansion coefficient is also defined for this material. The time evolution of the temperature is given by the result data structure EVOTH (of type evol_ther). The reference temperature (the one at which the expansion is zero) is 20 degrees.

```text
CHMAT = AFFE_MATERIAU (MAILLAGE = MA,
   AFFE =_F(TOUT='OUI', MATER = MAT, ),
   AFFE_VARC=_F(NOM_VARC='TEMP', EVOL =EVOTH, VALE_REF=20. ),
   )
```

Example 3: mechanics with thermal expansion + complex modeling

In the previous example, the thermal evolution (EVOTH) applies to all the elements of the model. For some complex modelings this may be unrealistic. The keyword AFFE_VARC/NOM_VARC='TEMP' must then be repeated to assign different thermal evolutions to different parts of the model.

In the following example, the model is a 3D model in which steel reinforcing bars are embedded. A thermal calculation was run beforehand without the bars, giving a result called EVOTH3D. The temperature at the nodes of the bar elements is therefore unknown. If the temperature of the bars can be estimated by other means (measurements, ...) and is stored in the field (TEMP_ARM), the mechanical thermal-expansion calculation can then be run with the following material field:

```text
CHMAT = AFFE_MATERIAU (MAILLAGE = MA,
  AFFE =_F(... ),
  AFFE_VARC=(
   _F(NOM_VARC='TEMP', GROUP_MA='VOLUM', EVOL =EVOTH3D, VALE_REF=20. ),
   _F(NOM_VARC='TEMP', GROUP_MA='ARMA', CHAM_GD =TEMP_ARM, VALE_REF=20. ),
))
```

Example 4: mechanics with the influence of irradiation

The material MAT, some of whose parameters are functions of irradiation, is assigned to the whole mesh. The time evolution of the irradiation is given by the result data structure EVOL = FLUENC.

```text
CHMAT = AFFE_MATERIAU (MAILLAGE = MA,
   AFFE =_F(TOUT='OUI', MATER = MAT, ),
   AFFE_VARC=_F(NOM_VARC='IRRA', EVOL =FLUENC, ),
   )
```

Example 5: mechanical calculation with an imposed Young's modulus field

This example (from the test case ssnv130c) shows how to use a Young's modulus field assumed known (CHYOUNG). For example, this field is read from a file (LIRE_CHAMP) or is the result of a calculation. The « trick » is to define a material whose Young's modulus (keyword ELAS/E) is the "identity" function of the variable 'NEUT1', and to assign the field CHYOUNG as the external state variable 'NEUT1'.

```text
CHYOUNG= ...
NU_F=DEFI_CONSTANTE( VALE=0.3 )
E_F = DEFI_FONCTION(NOM_PARA='NEUT1',VALE=(-1.E-9,-1.E-9, 1.E+9,1.E+9))
MA=DEFI_MATERIAU(ELAS_FO=_F(E=E_F, NU=NU_F,),);
CM=AFFE_MATERIAU( MAILLAGE=M,
                  AFFE=_F(TOUT= 'OUI', MATER= MA),
                  AFFE_VARC=_F(NOM_VARC='NEUT1', CHAM_GD=CHYOUNG),
                  )
```
