# POURSUITE procedure

## 1 Purpose

Continue a study from its save in JEVEUX format.

The apparently complex syntax of this procedure should not worry the user: a call with the default operands is enough in most cases: POURSUITE ( )

This command is used in exactly the same way as DEBUT. The keywords that behave the same in DEBUT and POURSUITE are described only in [U4.11.01].

## 3 How it works

This procedure also allocates the memory resources needed to continue the calculation.

The operands of the command correspond to those of the DEBUT procedure [U4.11.01]. They specify some resources allocated to the new execution.

The study started earlier continues with a set of commands that begins with POURSUITE and ends with FIN [U4.11.02].

When executed, the POURSUITE procedure does the following:

- defines the logical units of the files used for printing,
- allocates the files associated with the databases managed by JEVEUX,
- reads the command catalogs but not the element catalogs, which were copied to the database during the first execution.

The operands are used to redirect the various files to logical units other than the default ones, or to adjust some file parameters.

Simple Python objects (of variable type) created during a previous execution are kept in a file associated with the JEVEUX database (pick.*). When the POURSUITE procedure runs, these objects are regenerated and can therefore be used under the name they were created with.

Note: Python objects of type class, function and type are not saved in the pickle. See the Examples paragraph for one possible way of working.

## 4 Operands

The keywords LANG and DEBUG are the same as in the DEBUT procedure [U4.11.01].

The keyword BASE is different for the POURSUITE procedure.

### 4.1 Keyword BASE

```text
BASE =
```

This keyword redefines the parameters of the direct-access files associated with the «base de données» (databases) when the default ones are not wanted. The maximum size of the associated file or files, and therefore the maximum number of records, can be redefined with the parameter passed on the command line after the keyword

In POURSUITE mode, some characteristics of the GLOBALE database can no longer be changed. Default values of the parameters associated with the databases

```text
VOLATILE
   NMAX_ENRE       62914
   LONG_ENRE        100    K mots
   LONG_REPE       2000
```

A word is 8 bytes on a 64-bit platform and 4 bytes on a 32-bit platform.

<!-- page 4 -->

Under Linux 64, the POURSUITE procedure with the default values allocates a direct-access file of at most 62914 records of 100 Kwords (K is 1024) for the 'VOLATILE' database.

Note:

The real size of the file is dynamic; it depends on the volume of information actually stored. This size is limited by the operating conditions and by a parameter among the values that characterize the platform. On the reference Linux 64-bit platform, the initial size is set to 48 GB. This value is used to size 2 objects used by the memory manager, and it is changed automatically during the execution if needed. It can be changed by passing an argument on the command line of the executable after the keyword « --max_base taille », where `taille` is a real value in MB. For the Globale database, which can be saved and reused as input of a calculation, the initial maximum size in « POURSUITE » is kept as it is if the parameter « --max_base » is not used, but it can be redefined in this way if needed.

#### 4.1.1 Operand FICHIER

```text
♦  FICHIER =
```

Symbolic name of the database concerned.

Only the parameter of the 'VOLATILE' database can be redefined.

#### 4.1.2 Operands LONG_ENRE / NMAX_ENRE / LONG_REPE

Definition of the database parameters (direct-access files).

```text
/  |  LONG_ENRE = lenr
```

lenr is the record length, in Kwords, of the direct-access files used.

Note:

The JEVEUX memory manager uses this parameter to tell two kinds of objects apart: large objects, which are split into as many records as needed, and small objects, which are accumulated in a buffer the size of one record before being unloaded.

```text
|  NMAX_ENRE = nenr
```

nenr is the default number of records. This value is determined from LONG_ENRE and from an operating parameter, set under LINUX64 to 12 GB (51 539 607 552 bytes), for the maximum size of the file associated with a database.

Note:

The two operands LONG_ENRE and NMAX_ENRE must be used with care: misuse can stop the program abruptly when the direct-access files are full. The consistency between the maximum file size and the product of the two parameters LONG_ENRE and NMAX _ENRE is checked at the start of the execution.

```text
|  LONG_REPE = lrep
```

lrep is the initial length of the directory (maximum number of objects JEVEUX can address). The memory manager manages it dynamically and extends the directory and all the associated system objects as needed.

### 4.2 Keyword CODE

This keyword turns on the generation of the .code file. Reserved for test cases, it is a simplified version of the CODE keyword of DEBUT.

## 5 Examples of use

The standard use of this procedure is:

```text
POURSUITE()
```

Python does not save the functions and classes defined in the main file (it only remembers in which Python module they were defined). This is the case of the code_aster command file. To use functions or classes and find them again in a continuation, they must be defined in an external module: - Take the module userpkg/usermod.py:

```text
def pyfunc(x) :
    return x * 2
```

- In the first set of commands, one would write:

```text
DEBUT()
from userpkg import usermod
form = FORMULE(NOM_PARA='X', VALE='pyfunc(X)', pyfunc=usermod.pyfunc)
assert form(2) == 4
FIN()
```

- Then:

```text
POURSUITE(PAR_LOT='NON')
assert form(2) == 4
FIN()
```

For this, add the directory userpkg, of type nom, to the study. It is important to understand that when reading back, Python tries to import the module userpkg.usermod, so it must find it in the same place. Moreover, when importing this module, Python executes the instructions it finds there. For this reason, do not create objects in the main body of an imported module (they would be created at each import and clutter the database). Create them in functions that run only on request.
