# DEFI_FONCTION operator

## 1 Purpose

Define a real or complex function of one real variable. This operator defines, for example, material properties that depend on temperature, or boundary conditions that depend on a space variable or on time.

The object produced by this operator is of type `fonction`.

<!-- page 2 -->

## 2 Syntax

```text
f  [fonction]   =  DEFI_FONCTION (
                ♦  NOM_PARA  =   np,
                ◊  NOM_RESU  =   /  ’TOUTRESU’,               [DEFAUT]
                                 /  nr,                       [K8]
                ♦  /   VALE         =  lv,                    [l_R]
                   /   VALE_C       =  lv,                    [l_C]
                   /   VALE_PARA    =  la,                    [listr8]
                       ♦  VALE_FONC    =   lo,                [listr8]
                   /   ABSCISSE     =  labs,                  [l_R]
                       ♦  ORDONNEE     =   lord,              [l_R]
                   /   NOEUD_PARA   =  lno,                   [l_noeud]
                       ♦  MAILLAGE     =   ma,                [maillage]
                       ♦  VALE_Y       =   ly,                [l_R]
                ◊  PROL_DROITE   =  /  ’CONSTANT’,
                                    /  ’LINEAIRE’,
                                    /  ’EXCLU’,               [DEFAUT]
                ◊  PROL_GAUCHE   =  /  ’CONSTANT’,
                                    /  ’LINEAIRE’,
                                    /  ’EXCLU’,               [DEFAUT]
                ◊  INTERPOL  =   |  ’LIN’,                    [DEFAUT]
                                 |  ’LOG’,
                ◊  INFO   =      /  1,                        [DEFAUT]
                                 /  2,
                ◊  VERIF  =  |   ’CROISSANT’,                 [DEFAUT]
                             |   ’NON’,
                ◊  TITRE  =  ti,                              [l_Kn]
                                 )
```

### 3.2 Operand NOM_RESU

```text
◊  NOM_RESU = nr
```

Gives the name of the result (8 characters). The function created is nr = f(np). Note: some commands ( CALC_FONCTION , DEFI_MATERIAU …) check that the names of the parameter and of the result are consistent with their context. For example, a tensile curve is expected as a function with NOM_PARA=’EPSI’ and NOM_RESU=’SIGM’.

### 3.3 Operand VALE

```text
/  VALE = lv
```

lv is the list of values (x , y , …, x , y ), in this order:

```text
1    1       n    n
```

- x , y (the first value of the parameter and the corresponding value of the result), 1 1
- ... ,
- x , y (the last value of the parameter and the corresponding value of the result). n n

Note: the list of values lv must be given in increasing order of the abscissas (x).

### 3.4 Operand VALE_C

```text
/  VALE_C = lv
```

lv is the list of values (x, y, z, …, x , y , z ) with:

```text
n    n    n
```

- x values of the parameter

```text
i
```

- ... ,
- y , z the real part and the imaginary part of the complex function for this parameter. i i

### 3.5 Operands ABSCISSE / ORDONNEE

```text
/  ABSCISSE = labs
/  ORDONNEE = lord
```

The abscissas and ordinates of the function are given separately as lists of real values (x , x , …, x ) for ABSCISSE and (y , y , …, y ) for ORDONNEE. The two 1 2 n 1 2 n lists must have the same length. <!-- equation -->

### 3.6 Operand VALE_PARA / VALE_FONC

```text
/  VALE_PARA = la
/  VALE_FONC = lo  [ref 1]
```

Works like ABSCISSE, ORDONNEE except that the lists are given as listr8 objects produced by DEFI_LIST_REEL [U4.34.01].

<!-- page 5 -->

VALE_PARA and VALE_FONC must have the same length, otherwise the command stops with an error.

### 3.7 Operand NOEUD_PARA

```text
/  NOEUD_PARA = lno
```

lno is the list of nodes that defines the abscissas of the function. The abscissas are the curvilinear abscissas of the nodes along the curve they define.

### 3.8 Operands PROL_DROITE and PROL_GAUCHE

```text
◊  PROL_DROITEetPROL_GAUCHE =
```

Define the type of extension to the right (to the left) of the domain of definition of the variable:

- ’CONSTANT’ for an extension with the last (or first) value of the function,
- ’LINEAIRE’ for an extension along the first segment defined (PROL_GAUCHE) or the last segment defined (PROL_DROITE),
- ’EXCLU’ if extrapolating values outside the domain of definition of the parameter is forbidden (in this case, if a calculation asks for a value of the function outside the domain of definition, the code stops with a fatal error).

For example:

```text
•  PROL_DROITE = ’CONSTANT’ , PROL_GAUCHE = ’CONSTANT’
               y
```

|   | x 1 LINEA |   |   |   |   |
|---|---|---|---|---|---|
| y |   |   |   |   |   |

```text
•  PROL_DROITE = ’LINEAIRE’, PROL_GAUCHE = ’EXCLU’
```

```text
x  x      x    x       x
         1    2       n­1   n
```

Note: the extension type and the interpolation type are independent of each other.

### 3.9 Operand INTERPOL

```text
◊  INTERPOL =
```

Type of interpolation of the function between the values of its domain of definition: one type for the interpolation of the parameter and one for the interpolation of the function. It is given as a list of texts among:

```text
INTERPOL = (’LIN’, ’LOG’)
```

’LIN’ : linear,

’LOG’ : logarithmic,

Note: if only one value is given, it is used for both the interpolation of the parameter and that of the function. INTERPOL = ’LOG’ is equivalent to ( ’LOG’, ’LOG’).

### 3.10 Operand INFO

◊ INFO = Gives the print options for the MESSAGE file. 1 : no printout (default option)

2 : printout of the parameters plus the list of the first 10 values in increasing order of the parameter

### 3.11 Operand VERIF

```text
◊  VERIF =
```

The operator DEFI_FONCTION checks that the abscissas are strictly increasing. If not, an error is raised. This is the default behavior, VERIF is ’CROISSANT’. The user can skip this check with VERIF=’NON’. In this case, the function is reordered by increasing abscissas. A warning is issued if the abscissas of the function were not increasing. The abscissas must however be strictly monotonic.

### 3.12 Operand TITRE

```text
◊  TITRE = ti
```

Title attached to the object produced by this operator [U4.03.01].

### 3.13 Operands MAILLAGE and VALE_Y

These two keywords must be given if the function is defined from NOEUD_PARA.

```text
MAILLAGE = ma
```

Name of the mesh associated with the list of nodes lno.

```text
VALE_Y = lv
```

List of the ordinate values of the function.

## 4 Definition of a function of time

### 4.1 Function and variables entered as reals

Definition of a (piecewise linear) function of time (parameter INST).

```text
EX_1 = DEFI_FONCTION  (
               NOM_PARA=’INST’,
               VALE = (  0. ,­1.,­1.
                         1. , 0.,­1.
                                      2
                         3. , 1.,
                         6. , 2., ),  1
            PROL_GAUCHE=’CONSTANT’,    0
                                          1   3   6    t
                                     ­1
            PROL_DROITE=’LINEAIRE’,
                        ) ;
```

### 4.2 Function and variables entered as listr8 objects

This function can be defined with objects of type listr8 created by the operator DEFI_LIST_REEL [U4.34.01]:

```text
ABSCISSE = DEFI_LIST_REEL (   DEBUT = 0. ,
                INTERVALLE =  ( _F ( JUSQU_A = 1., NOMBRE = 1,),
                                 _F ( JUSQU_A = 3., NOMBRE = 1,),
                                 _F ( JUSQU_A = 6., NOMBRE = 1,),)
                          )
ORDONNEE = DEFI_LIST_REEL (   DEBUT = -1. ,
                INTERVALLE =   ( _F (JUSQU_A = 0., NOMBRE = 1,),
                                 _F (JUSQU_A = 1., NOMBRE = 1,),
                                 _F (JUSQU_A = 2., NOMBRE = 1,),)
                          )
EX_2 = DEFI_FONCTION   (  NOM_PARA    = ’INST’,
                          VALE_PARA   = ABSCISSE,
                          VALE_FONC   = ORDONNEE,
                          PROL_DROITE = ’CONSTANT’,
                          PROL_GAUCHE = ’LINEAIRE’,
                       )
```

Note: this example is obviously far too complicated to define the function in question. It only shows the principle of this option, which becomes useful for functions defined at a large number of points. Another reason to use the definition by DEFI_LIST_REEL is when the lists are needed as the argument of another operator (list of times of an evolution calculation THER_LINEAIRE , DYNA_LINE_TRAN , …); this avoids duplicating information.
