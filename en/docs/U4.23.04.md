# MODI_MAILLAGE operator

## 1 Purpose

Make changes to an existing mesh. The possible changes are:

- reorient boundary elements used to apply a pressure,
- check the orientation of the normals on shell elements,
- reorient the elements of a single layer of joint elements,
- update the mesh from a deformed shape computed earlier,
- in a mesh with a crack front, move the mid-side nodes of the edges touching the crack front to the quarter of these edges,
- translate a mesh,
- impose one or more rotations about arbitrary axes on a mesh,
- generate a mesh symmetric with respect to a plane in 3D or a line in 2D.
- compute the curvilinear abscissa along a line made of line elements (SEG)
- change the coordinates of the nodes randomly

Produces a data structure of type `maillage` or modifies the data structure (reentrant operator).

## 3 Operands

### 3.1 Operand MAILLAGE

```text
♦  MAILLAGE = ma,
```

Mesh of type [maillage] to which the changes and/or checks apply.

Note: a 3D change can be applied to an initially two-dimensional mesh.

### 3.2 Operand INFO

```text
◊  INFO =
```

Gives the print level of the results of the operator,

1 = no printout, 2 = printout of the elements whose connectivity was changed, including the old and new connectivities.

The printouts go to the 'MESSAGE' file.

### 3.3 Keyword ORIE_FISSURE

```text
◊  ORIE_FISSURE =
```

This keyword reorients (if needed) the elements of a group that forms a "single layer" of elements. It works in 2D or 3D, with a linear or quadratic mesh [Figure 3.4-a].

Figure 3.4-a

This keyword is currently used to reorient joint elements and interface elements (modeling types AXIS_xxx, PLAN_xxx and 3D_xxx with xxx=JOINT or INTERFACE).

The user gives (with the keyword GROUP_MA) the elements that are candidates for reorientation (the "single layer"). These elements must be "prisms" (QUAD in 2D, HEXA and PENTA in 3D).

The direction "across" the layer is found topologically (not from a flatness criterion). To be reoriented, the elements of the layer must rest (through the bases of the prisms) on other elements of the same dimension (2D or 3D) that do not belong to the group of elements to reorient.

*[Figure, page 5: not extracted]*

Take the (2D) mesh shown here.

The group of the 3 elements A, B and C is to be reoriented. For elements A and B, the supporting elements (above and below) give an unambiguous transverse orientation (vertical).

<!-- page 6 -->

Element C, however, has 3 supporting elements (top, bottom, right) and the transverse direction cannot be found. The reorientation algorithm fails.

Note:

The "reorientation" meant here actually changes how the connectivity of the elements is defined. For example, in 2D, the convention is that sides 2 and 4 of the quadrangles are across the layer.

```text
♦  GROUP_MA= l_gm,
```

List of the element groups whose orientation is to be checked (and possibly changed).

### 3.4 Keyword DEFORMEE

```text
♦  DEFORME /OPTION ='TRAN'
```

Option that adds to the initial geometry of the mesh ma:

  - the TRANslation values (dx, dy (+ dz in 3D)) of the displacement field depl given by the keyword DEPL;
  - or a random quantity.

```text
/  DEPL = depl ,
```

Displacement field used to update the geometry

```text
/  ALEA = epsi ,
```

A random quantity (delta) is added to each coordinate of each node of the mesh.

This quantity is given by the formula: delta=epsi*dim*alea() where:

  - epsi is a number given by the user (1.e-8 for example)
  - dim is the size of the mesh in the direction of the component (X,Y or Z)
  - alea() is a function that returns a pseudo-random number in the interval
  - [-1,1].

Note: changing the coordinates of a mesh randomly is, a priori, a « developer » feature. It is dangerous in some situations: very flat elements (joints, ...)

### 3.5 Keyword ORIE_PEAU

```text
◊  ORIE_PEAU =
```

This keyword reorients boundary elements so that their normals are consistent (pointing out of the material). It is valid for a two-dimensional (2D) or three-dimensional (3D) study. It is an essential first step if, for example, a pressure load is to be applied on this « skin ».

```text
♦  GROUP_MA_PEAU = lgrma,           [l_gr_ma]
```

Element groups to reorient.

The elements are oriented so that the normal points outward. For each boundary element (edge or face), the code looks for the « volume » element it « borders », and orients the boundary element so that its normal points opposite to the vector from its first node to the centroid of the volume element.

Sometimes the « skin » to orient lies inside the material (for example in a calculation where elements are progressively added to or removed from the model: modeling of an excavation, or of a construction in layers). The orientation algorithm above then fails, because there are usually 2 volume elements on either side of the skin element, and the code cannot tell which one to use to orient it.

For this, the optional keyword GROUP_MA_INTERNE was introduced. It lets the user say which « internal » elements are used to orient the skin elements.

Example:

Take 1 group of skin elements (GPEAU) to orient with a normal pointing outward. It must be stated that it is the skin of the group of "volume" elements GV2. Write:

```text
ORIE_PEAU=_F(GROUP_MA_PEAU='GPEAU', GROUP_MA_INTERNE='GV2'),
```

### 3.6 Keyword ORIE_NORM_COQUE

```text
◊  ORIE_NORM_COQUE = _F(
```

This keyword checks that, in a list of surface elements (shells), the normals are consistent with each other. If not, some elements are reoriented.

```text
♦  GROUP_MA =   lgrma,           [l_gr_ma]
```

Groups of surface elements to reorient. The elements of lgrma must form a "connected" group so that they can be reoriented by continuity.

The direction of the orientation can be imposed with the keywords GROUP_NO/VECT_NORM. Otherwise the orientation kept is that of the 1st element of lgrma, which is not necessarily the 1st element of the 1st GROUP_MA! So always use the keyword VECT_NORM.

```text
◊  VECT_NORM = (n1, n2, [n3]),   [l_R]
```

ni: 2 or 3 components (depending on the dimension) of the normal vector. The node that carries this normal must be given too:

```text
◊  GROUP_NO  =  grno,     [gr_no]
```

grno must be a GROUP_NO that contains only one node. The normal chosen is the one at an acute angle with the vector given by VECT_NORM.

Note: if the user does not give GROUP_NO, the code automatically picks one of the nodes of GROUP_MA . So take care when defining the latter, so that the normal is well defined over all the elements. In particular, avoid cases where the group does not define a nearly flat topological zone.

### 3.7 Keyword ORIE_LIGNE

```text
◊  ORIE_LIGNE = _F(
```

This keyword checks that, in a list of line elements (beams), the tangents are consistent with each other. If not, some elements are reoriented.

```text
♦  GROUP_MA =   lgrma,           [l_gr_ma]
```

Groups of line elements to reorient. The elements of lgrma must form a "connected" group so that they can be reoriented by continuity.

The direction of the orientation can be imposed with the keywords GROUP_NO/VECT_TANG. Otherwise the orientation kept is that of the 1st element of lgrma, which is not necessarily the first element of the first GROUP_MA! So always use the keyword VECT_TANG.

```text
◊  VECT_TANG = (n1, n2, [n3]),   [l_R]
```

ni: 2 or 3 components (depending on the dimension) of the tangent vector. The node that carries this tangent must be given too:

```text
◊  GROUP_NO  =  grno,     [gr_no]
```

grno must be a GROUP_NO that contains only one node. The tangent chosen is the one at an acute angle with the vector given by VECT_TANG.

### 3.8 Keyword MODI_MAILLE

```text
♦  OPTION = 'NOEUD_QUART' ,
```

Moves the mid-side nodes of the edges touching the crack front to the quarter of these edges (toward the crack front).

```text
♦  /   GROUP_MA_FOND = lgma_fo,  [l_gr_ma]
   /   GROUP_NO_FOND = lgno_fo,  [l_gr_no]
```

In 2D, give the node of the crack front (with GROUP_NO_FOND).

In 3D, give either the nodes of the crack front or the SEG3 elements of the crack front (not the elements of the crack lips, nor the material elements resting on the front).

### 3.9 Keyword TRANSLATION

Warning

This feature can be combined with ROTATION , but these operations do not commute. The translation is always done before the rotation. This feature cannot be combined with SYMETRIE .

```text
◊  TRANSLATION = (n1, n2, [n3]),    [l_R]
```

Simple keyword to translate a mesh along a vector.

### 3.10 Keyword ROTATION

### 3.12 Keyword MODI_BASE

Warning

This feature is not allowed with ROTATION and SYMETRIE.

```text
◊  MODI_BASE =
```

Factor keyword to change the basis in which the coordinates of a mesh are expressed. The change of coordinate system is always between 2 orthonormal bases.

```text
♦  VECT_X    =  (n1, n2, [n3]),     [l_R]
```

Coordinates of the first vector of the new basis, of any norm.

```text
◊  VECT_Y    =  (n1, n2, [n3]),     [l_R]
```

Coordinates of the second vector of the new basis (not used in 2D), also of any norm.

In 2D, giving the axis VECT_X is enough: Code_Aster builds the second vector automatically to define a direct orthogonal basis. A check verifies that VECT_X has a nonzero norm.

In 3D, the code checks that VECT_X and VECT_Y have nonzero norms and are orthogonal. The third vector that completes the basis is the cross product of VECT_X and VECT_Y. This ensures a direct orthogonal basis.

Then, in all cases (2D and 3D), the basis vectors are normalized to 1, so the user does not need to worry about it. The result is a direct orthonormal basis.

### 3.13 Keyword SYMETRIE

Warning

This feature cannot be combined with TRANSLATION , ROTATION , ECHELLE and MODI_BASE .

```text
♦  POINT     =  (n1, n2, [n3])      [l_R]
```

Coordinates of a point on the line in 2D or in the plane in 3D.

```text
♦  AXE_1  =  (n1, n2, [n3])         [l_R]
```

Direction vector of the line in 2D, or 1st vector that describes the plane.

```text
◊  AXE_2  =  (n1, n2, n3)           [l_R]
```

2nd vector that describes the plane.

In 2D, the symmetry is with respect to a line in the OXY plane. To define this line, give its direction vector (AXE_1) and a point (POINT) on the line. In 3D, the symmetry is with respect to a plane. To define this plane, give 2 vectors of the plane (AXE_1, AXE_2) and a point (POINT) in the plane.

In all cases (2D or 3D), the symmetry is made with respect to a plane. In 2D, the second vector needed to define the plane is set to AXE_2 = (0.0, 0.0, -1.0).

### 3.14 Keyword ABSC_CURV

```text
◊   ABSC_CURV = _F (...),
```

Computes the curvilinear abscissa for all the SEG elements given with the keywords GROUP_MA or TOUT='OUI'. For each node of these elements, its curvilinear abscissa is computed taking any curvature into account.

The keyword GROUP_NO_ORIG lets the user choose the origin of the curvilinear abscissas (the node where the abscissa is zero). The origin must be one of the ends of the line on which the curvilinear abscissa is computed.

This option is needed, for example, for a modal calculation of a tube with external and internal fluid, when the density of the external fluid is defined as a function of the curvilinear abscissa.
