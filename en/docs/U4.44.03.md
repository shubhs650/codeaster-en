# AFFE_CHAR_CINE and AFFE_CHAR_CINE_F operators

## 1 Purpose

Define a load of the "imposed degrees of freedom" type.

This command can be used with a mechanical, thermal or acoustic model. These "kinematic" conditions are processed without Lagrange-multiplier enforcement, and therefore without adding Lagrange degrees of freedom.

1) For AFFE_CHAR_CINE (except for the EVOL_IMPO case), the values assigned depend on no parameter and are defined by real values (mechanical or thermal) or complex values (acoustic). These values can be zero (fixing). 2) For AFFE_CHAR_CINE_F, the values assigned are functions of one (or more) parameters chosen from INST ,X ,Y ,Z. <!-- equation -->

Produces a data structure of type char_cine_* .

## 3 General

These two commands create objects of type char_cine_* ( _meca/_ther ).

The command AFFE_CHAR_CINE can also create objects of type char_cine_acou .

These types differ from the type `charge` created by the commands AFFE_CHAR_MECA [U4.44.01], AFFE_CHAR_THER [U4.44.02] or AFFE_CHAR_ACOU [U4.44.04]).

The objects created are therefore not interchangeable.

The advantage of "kinematic" loads is that they do not increase the number of unknowns of the systems to solve, unlike the Lagrange-multiplier enforcement (LAGRANGE multipliers) used in the commands that produce an object of type `charge` .

On the other hand, these loads have the following limitations:

- they can only be used for relations of the "imposed DOF" type (not for linear relations),
- these loads are not yet accepted by all global commands. The commands that accept them today are:

```text
-  MECA_ STATIQUE, STAT_NON_LINE, DYNA_NON_LINE
-  THER_LINEAIRE
```

- for a calculation that does not use the global commands (assembly of a matrix, then solution), the sequence of commands is more complicated than with "ordinary" loads, as example 2 shows [§ 5.2].

## 4 Operands

### 4.1 Operands in general

The operands under the factor keywords MECA_IMPO , THER_IMPO and ACOU_IMPO are of two kinds:

- the operands that give the geometric entities the loads are assigned to (keywords GROUP_MA , GROUP_NO…). The arguments of these operands are the same for both operators.
- the operands that give the values assigned ( DX , DY , DZ , etc …). These operands mean the same for both operators. Their arguments are all of real type for the operator AFFE_CHAR_CINE and of function (or formule ) type for the operator AFFE_CHAR_CINE_F .

This is true with one exception: the factor keyword ACOU_IMPO (which does not exist in the command AFFE_CHAR_CINE_F ) is always of complex type.

So in this document, unless expressly stated otherwise, the two operators AFFE_CHAR_CINE and AFFE_CHAR_CINE_F are not distinguished.

In general, the entities to which values must be assigned are defined by nodes:

1) either by the operand TOUT = 'OUI', which designates all the nodes of the mesh, 2) or by the operand GROUP_NO, which designates a list of node groups, 3) or by the operand GROUP_MA, which designates all the nodes carried by the elements of the GROUP_MA lists.

### 4.2 Behavior when values are overwritten:

#### 4.2.1 Overwriting within a single AFFE_CHAR_CINE command

When several occurrences of MECA_IMPO (or THER_IMPO , ...) are used within the same command and some nodes are assigned several times, the last occurrence wins. For example:

```text
chcine= AFFE_CHAR_CINE( MECA_IMPO=(
                 _F( TOUT='OUI',   DX= 1., ...)
                 _F( GROUP_NO='GN3',   DX= 3., ...)
```

In this case, the imposed displacement DX of node GN3 is: 3.

#### 4.2.2 Overwriting between several AFFE_CHAR_CINE commands

If several different commands are used, the behavior is different. For example:

```text
chcin1= AFFE_CHAR_CINE( MECA_IMPO= _F( TOUT='OUI',   DX= 1., ...)
chcin2= AFFE_CHAR_CINE( MECA_IMPO= _F( GROUP_NO='GN3',   DX= 3., ...)
```

In this case, the imposed displacement DX of node GN3 is: 4 (because 1+3)

#### 4.2.3 Overwriting between AFFE_CHAR_CINE and AFFE_CHAR_MECA

If the commands AFFE_CHAR_MECA and AFFE_CHAR_CINE are "mixed", the code stops with a fatal error ( FACTOR_41 ) explaining that there is a redundant fixing relation ( NOEUD N3 / DX).

### 4.4 Keyword MECA_IMPO

#### 4.4.1 Purpose

Factor keyword used to impose a displacement value at nodes, defined component by component in the global coordinate system.

These boundary conditions are then processed by the so-called elimination method for imposed degrees of freedom (that is, without Lagrange-multiplier enforcement, unlike the processing of the same kind of boundary condition with the operators AFFE_CHAR_MECA or AFFE_CHAR_MECA_F [U4.44.01]).

| DX = ux or uxf | Value of the translation displacement component |
|---|---|

| DRX = drx or drxf | Value of the rotation displacement component |

Warning:

### 4.5 Keyword THER_IMPO

#### 4.5.1 Purpose

Factor keyword used to impose a nodal temperature value at nodes.

These boundary conditions are then processed by the so-called elimination method for imposed degrees of freedom (that is, without Lagrange-multiplier enforcement, unlike the processing of the same kind of boundary condition with the operators AFFE_CHAR_THER or AFFE_CHAR_THER_F [U4.44.02])

#### 4.5.2 Syntax

```text

                       ♦  |  TEMP     =    t     ,         [R]

                             | GROUP_MA =  lgma  ,         [l_gr_maille]
                       ♦  |  TEMP     =    ft    ,         [fonction(                                                         *)]
                          |  TEMP_SUP =    ftsup ,         [fonction(                                                         *)]
                          |  TEMP_INF =    ftinf ,         [fonction(                                                         *)]
                ), ),

```

#### 4.5.3 Operands

```text
|  TEMP
```

Temperature imposed on the nodes (or on the mid-surface for thermal shells)

```text
|  TEMP_INF
```

Temperature imposed on the lower face of thermal shell elements.

```text
|  TEMP_SUP
```

Temperature imposed on the upper face of thermal shell elements.

For shells, the lower and upper faces are defined, element by element, by the direction of the outward normal deduced from the node numbering: see FACE_IMPO of AFFE_CHAR_MECA [U4.44.01].

### 4.6 Keyword ACOU_IMPO

#### 4.6.1 Purpose

Factor keyword used to impose an acoustic pressure value at nodes.

These boundary conditions are then processed by the so-called elimination method for imposed degrees of freedom (that is, without Lagrange-multiplier enforcement, unlike the processing of the same kind of boundary condition with the operator AFFE_CHAR_ACOU [U4.44.04]).

#### 4.6.2 Syntax

```text
PourAFFE_CHAR_CINE
    / ACOU_IMPO = (_F  (  ♦   /  TOUT =          'OUI'  ,
                                 | GROUP_NO = lgno   ,        [l_gr_noeud]
                                 | GROUP_MA = lgma   ,        [l_gr_maille]
                          ♦  PRES =              p      ,     [C]
                   ),  ),
PourAFFE_CHAR_CINE_F :
```

No keyword ACOU_IMPO, because there is no complex function yet.

#### 4.6.3 Operands

```text
PRES
```

Value of the complex acoustic pressure imposed on the given node(s).

### 4.7 Keyword EVOL_IMPO

```text
/  EVOL_IMPO = evoimp     /  [evol_ther]
                          /  [evol_elas]
                          /  [evol_noli]
   ◊   NOM_CMP = lcmp        [l_TXM]
```

This keyword allows "structural zoom" (see for example the test zzzz230a ).

It imposes all the DOFs of the evolution evoimp as if they were functions of time. This is available for the data structures evol_elas, evol_noli and evol_ther.

For a « zoom structural », impose the DOFs only on the nodes of the boundary of the « zoom » model. This generally means projecting the « grossier » (coarse) calculation onto the boundary elements of the « zoom » model.

If, in addition, not all components are to be imposed, use the keyword NOM_CMP to choose the components to impose (default: all).

Notes:

- Take care not to use several EVOL_IMPO on common zones (otherwise the imposed values add up)
- Take care when using FONC_MULT with EVOL_IMPO: the result may not be what you expect!
<!-- page 10 -->

- The EVOL_IMPO is used for any time value between tmin and tmax (the extreme times of the EVOL_IMPO transient). Outside this interval, a fatal error is issued (extrapolation forbidden).
- If the EVOl_IMPO has only one time, a "constant" extension is allowed and a warning is issued.

## 5 Examples

### 5.1 Imposed degrees of freedom in mechanics

```text
chcine =  AFFE_CHAR_CINE  (MODELE = mo,
             MECA_IMPO=(
                _F (TOUT = 'OUI' , DRZ = 0.),
                _F (GROUP_NO = 'bord1',    DX =  0., DY =  0.,DZ =   0.,
                                           DRX = 0., DRY = 0.,)))
```

For this problem of a plate in the XY plane, all the rotation degrees of freedom about Z are fixed and the plate is clamped on its edge bord1 .

### 5.2 Kinematic and "ordinary" loads compared

#### 5.2.1 Global commands

```text
ch1   =   AFFE_CHAR_THER  ( ... )
ch2   =   AFFE_CHAR_CINE_F( TEMP_IMPO =_F ( ... ))
evoth =   THER_LINEAIRE   (  ...
                             EXCIT = ( _F (CHARGE = ch1),
                                       _F (CHARGE = ch2),)
                             ...)
```

There is no difference.

#### 5.2.2 "Step by step" calculation

Ordinary loads

```text
ch1    =  AFFE_CHAR_MECA ( ... )
mel    =  CALC_MATR_ELEM ( ... OPTION = 'RIGI_MECA'  , CHARGE = ch1)
matas  =  ASSE_MATRICE (  MATR_ELEM = mel ...)
matas  =  FACTORISER ( reuse = matas, MATR_ASSE = matas )
U      =  RESOUDRE (   MATR = matas ,  CHAM_NO = F )
```

Kinematic loads

```text
ch1    =  AFFE_CHAR_CINE ( ... )
mel    =  CALC_MATR_ELEM ( ... OPTION = 'RIGI_MECA' )
matas  =  ASSE_MATRICE (  MATR_ELEM = mel, ..., CHAR_CINE = ch1 )
matas  =  FACTORISER ( reuse = matas, MATR_ASSE = matas, )
vcine  =  CALC_CHAR_CINE ( ..., CHAR_CINE = ch2, )
U      =  RESOUDRE (   MATR = matas ,  CHAM_NO = F,
                       CHAM_CINE = vcine)
```

The terms induced by the kinematic loads are moved to the right-hand side, which requires the calculation of an extra field at nodes, vcine, with the command CALC_CHAR_CINE [U4.61.03].
