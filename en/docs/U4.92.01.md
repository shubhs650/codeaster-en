# TEST_RESU procedure

## 1 Purpose

Compare a value extracted from a data structure with a reference value given by the user.

This command tests a numeric value (integer, real or complex) extracted from an object already computed. Today one can test a component of a cham_no or a cham_elem, a component of a field extracted from a result, a parameter of a result, a 'global' value extracted from a field, or the content of any object of a user object.

The procedure then writes a conventional message:

- "OK" (if it passes),
- "NOOK" (otherwise).

followed by the value found, the reference value and the percentage of error. A non-regression value is always checked and, when possible, an analytical reference value, from an external source or from another Code_Aster calculation.

The commands TEST_FONCTION [U4.92.02] and TEST_TABLE [U4.92.03] test values extracted from functions and tables.

Note 1

The definition of the reference value is common to the commands TEST_RESU, TEST_TABLE, TEST_FONCTION and TEST_FICHIER. Not all keywords are available in all commands; see the comments. The integer type (_I) does not exist in TEST_FONCTION and TEST_FICHIER. The complex type (_C) does not exist in TEST_FICHIER and for OBJET. The string type (_K) exists only in TEST_FICHIER and TEST_TABLE. VALE_ABS does not exist for CARTE and TEST_FICHIER.

Note 2

The keywords CHAM_NO, CHAM_ELEM and CARTE test cham_no , cham_elem and carte objects. The keyword RESU is reserved for objects of type `resultat`. The keyword MAILLAGE tests a few (integer) characteristics of a mesh.

## 3 General

This command tests a scalar numeric value taken from an object of type cham_no, cham_elem, carte or `resultat`, against a non-regression value and, when possible, against an analytical reference value, from an external source or from another Code_Aster calculation.

Three kinds of numeric values can be tested:

- a component of a field (cham_no, cham_elem, carte, or a field that is part of a `resultat`),
- a parameter held in a result object,
- a global value of a field [§4.4].

To test a field component, choose a field [§4.1], then a component [§4.3].

To test a parameter, choose a step index [§4.1.4] and the name of the parameter.

The expected numeric value (real, complex or integer) is given as in [§4.7].

Note on non-regression tests: a non-regression test against a previously computed value is always made. The tolerance of this test (TOLE_MACHINE) must be very small and should not exceed the default value. In particular, the value should be the same (to at least 8 decimals) on all platforms. Moreover, this computed value should change only when the algorithm is modified or corrected. Any other change should alert the developer about the reliability of the programming.

Notes on tests in "generalized" data structures:

Generalized components (displacements, velocities or accelerations of a transient in modal space) can be tested. Be wary of this kind of test, though. The value of a generalized component depends entirely on the norm of the mode, and that norm is set arbitrarily. So without normalizing the norms first, the value of a generalized quantity is arbitrary. Finally, Code_Aster cannot fix the direction of a mode. For a multiple mode, this means that even once the modes are normalized, a generalized quantity can take any value. A simple mode can point in one direction or the opposite one, so one gets a generalized value or its opposite.

## 4 Operands

### 4.1 Selecting a field

To test a field, which can be a standalone field (cham_no, cham_elem or carte) or a field extracted from a result, use the factor keywords CHAM_NO, CHAM_ELEM, CARTE or RESU.

#### 4.1.1 "Standalone" fields

```text
♦  CHAM_GD = champ
```

Name of the cham_no , cham_elem or carte from which a value is extracted.

#### 4.1.2 Operand RESULTAT

```text
♦  RESULTAT = res
```

<!-- page 6 -->

Name of the `resultat` object processed.

#### 4.1.3 Operand NOM_CHAM

```text
♦  /  NOM_CHAM = nosymb
```

Symbolic name of the field to select.

#### 4.1.4 Selecting a step index

```text
♦  /  NUME_ORDRE = nuor,
```

Step index of the field (or parameter) wanted.

```text
/  NUME_MODE = numo,
/  INST      = inst,
/  FREQ      = freq,
/  NOEUD_CMP = (noeud, cmp),
/  NOM_CAS   = nocas,
/  ANGLE      =  ,
```

These keywords identify a step index in a `resultat` [U4.71.00].

They are called "access variables".

They are not all valid for all `resultat` types.

When the access is by a real value (ANGLE, FREQ, INST), the value given must not be ambiguous (cf [§4.7]).

### 4.2 Selecting a parameter in a result

To select a parameter in a result, give the step index wanted [§4.1.4] and the name of the parameter.

```text
♦  PARA = para
```

Name of the parameter wanted. This name depends on the type of the `resultat` object processed.

### 4.3 Selecting a component of a field

For a cham_no, a quantity is accessed by:

  - the name of a node group that contains the node carrying this quantity (and only that node).

For a cham_elem, a quantity is accessed by:

  - the name of an element group that contains the element (and only that element),
  - something that gives:
  - either the name of a group that contains a node of this element, for cham_elem "at nodes" (ELNO),
  - or the number of the GAUSS point, for cham_elem "at GAUSS points" (ELGA).

For a carte, a quantity is accessed by:

  - the name of an element group that contains the element,

```text
♦  GROUP_MA  = gma1
```

Designates the element at which the cham_elem or the carte is tested. The group must contain only one element.

```text
♦  GROUP_NO = grno
```

Name of the group that contains the node one of whose components is checked. The group must hold a single node.

<!-- page 7 -->

```text
/  POINT = nupoint
```

The integer nupoint gives the number of the GAUSS point whose value is tested (cham_elem "at GAUSS points").

```text
◊    SOUS_POIN T = nusp
```

The integer nusp gives the number of the sub-point whose value is wanted (cham_elem with sub-points, used by structural elements: beams, pipes, shells). For plates and multilayer shells, the sub-point number is the level in the stack of layers. Each layer is described by a lower, middle and upper skin. By convention, for N layers, this number runs from 1 to 3N, where the first point is at the lower skin of the first layer and the 3Nth point at the upper skin of the last layer (cf. [R3.07.03] and [R3.07.04] for the numbering of the layers).

For multifiber beams, this integer is the number of the fiber, whose numbering is described in the documentation [U4.26.01] and [R3.08.08].

For pipes, see the description in the document [R3.08.06].

```text
/  NOM_CMP = ncmp
```

Name of the component to test [U2.01.04].

```text
/  NOM_VARI = nvari
```

For internal variable fields (VARI_*), the name of the internal variable can be given (see [U4.51.11] for the naming rules of internal variables) instead of the name of the component (V1, ...).

### 4.4 Testing a field "globally"

Once a field is selected [§4.1], a quantity computed over the whole field can be tested. For this, NOM_CMP must not be given, so that all the components of the field are taken into account.

```text
/  TYPE_TEST = ‘SOMM_ABS’
```

The sum of the absolute values of the components of the field.

```text
/  TYPE_TEST = ‘SOMM’
```

The sum of the values of the components of the field.

```text
/  TYPE_TEST = ‘MAX’
```

The maximum of the values of the components of the field.

```text
/  TYPE_TEST = ‘MIN’
```

The minimum of the values of the components of the field.

### 4.5 Testing the content of a JEVEUX object

This feature is reserved for the developers of the code. Using it requires knowing the names of the JEVEUX objects that make up the user's objects. It is meant to check the non-regression of data structures other than RESULTAT, CHAMPS, TABLE and FONCTION.

#### 4.5.1 Operand NOM

```text
NOM = nomobj
```

Name of the jeveux object to test.

<!-- page 8 -->

Note:

The aim of this kind of test ( NOM + VALE_CALC/_I ) is to test a whole vector globally. Unfortunately the "sum" tested is a poor "check sum" of the object: a permutation inside the vector does not change it. A safer test is to print the object to a file ( IMPR_CO ), then test the content of that file with a real "check sum" ( TEST_FICHIER ).

#### 4.5.2 Operands CRITERE and PRECISON

See below [§4.7].

### 4.6 Factor keyword MAILLAGE.

This keyword validates the commands of the code that produce (or modify) meshes. It tests a few (integer) characteristics of meshes: number of elements, of nodes, of element groups, of node groups, number of elements in an element group and number of nodes in a node group.

#### 4.6.1 Operand MAILLAGE

```text
MAILLAGE = mailla
```

Name of the mesh to test.

#### 4.6.2 Operand CARA

Chooses the characteristic of the mesh to test: 'NB_MAILLE', 'NB_NOEUD', 'NB_GROUP_MA', 'NB_GROUP_NO', 'EXI_GROUP_MA' or 'EXI_GROUP_NO'.

#### 4.6.3 Operands NOM_GROUP_MA and NOM_GROUP_NO

These operands are used with CARA='EXI_GROUP_MA' (resp. CARA='EXI_GROUP_NO' ). They designate the group to test. In this case, the value tested (VALE_CALC_I or VALE_REFE_I) must contain the number of elements (or nodes) of the group.

### 4.7 Definition of the non-regression and reference values

A non-regression test against a previously computed value is always made, with a very small tolerance: keywords VALE_CALC and TOLE_MACHINE. As often as possible, a test against a reference value is added, from an analytical solution, a value from an external source or another modeling: keywords REFERENCE, VALE_REFE, PRECISION.

```text
♦  /  VALE_CALC = val
```

Real non-regression value. It is the value computed by Code_Aster. When this value is zero (below 1.e-16 in absolute value), the keyword ORDRE_GRANDEUR = ordgrd must be given. It only makes sense in absolute terms. The check is then: |val|≤tole∗ordgrd If ORDRE_GRANDEUR is not given while VALE_CALC is zero, the non-regression test is skipped (it shows as SKIP in the result file). Warning: in this case, a test with VALE_REFE is mandatory.

```text
/  VALE_CALC_C = val
```

Complex non-regression value.

```text
/  VALE_CALC_I = val
```

Integer non-regression value.

<!-- page 9 -->

```text
/  VALE_CALC_K = val
```

Non-regression character string. Only in TEST_FICHIER and TEST_TABLE.

```text
◊  TOLE_MACHINE = tole
```

Precision required (1.D–6 by default) to accept the computed value against the non-regression value (VALE_CALC). See ORDRE_GRANDEUR above.

```text
◊  VALE_ABS
```

| = ‘NON’ | the reference value and the value computed by Aster are compared as they are. |
|---|---|
| = ‘OUI’ | the reference value and the value computed by Aster are compared in |

absolute value.

```text
◊  CRITERE =
```

Type of test. Applies to the non-regression test and, if any, to the test against a reference value.

If v is the extracted value, the test is:

  - 'RELATIF': ∣val−v∣≤prec⋅∣val∣
  - 'ABSOLU': ∣val−v∣≤ prec

```text
◊  REFERENCE =
```

| / 'ANALYTIQUE' : | the reference value given is "analytical" |
|---|---|
| / 'SOURCE_EXTERNE' : | the reference value given comes from a program other than Code_Aster , from the literature, from a measurement, etc. |
| / 'AUTRE_ASTER' : | the reference value given is the one obtained by another Code_Aster calculation (another command, another modeling, a calculation option, ...) |

The presence of the keyword REFERENCE says that an external reference is available, and it requires the keywords VALE_REFE[_I/_C] and PRECISION.

```text
♦  VALE_REFE, VALE_REFE_C, VALE_REFE_I, VALE_REFE_K
```

Similar to the VALE_CALC keywords above. They give the value obtained from the external source.

```text
◊  PRECISION =
```

Precision required (1.D–3 by default) to accept the computed value against the reference value (VALE_REFE).

Note:

When the step index of a RESULTAT is defined by a real access variable ( FREQ , INST , ANGLE ), the step index must not be ambiguous. For this, the user defines a small interval around the requested value with the keywords CRITERE and TOLE_MACHINE .

In this case ("real" access) the keywords CRITERE and TOLE_MACHINE each expect 2 values: ( crit1 , crit2 ) and ( prec1 , prec2 ).

crit1 and prec1 apply to the non-regression value.

crit2 and prec2 set the search interval for the step index.

The default values of crit1 and prec1 are 'RELATIF' and 1.D-6.

<!-- page 10 -->

The default values of crit2 and prec2 are 'RELATIF' and 1.D-3.

crit2 and prec2 cannot be given explicitly without crit1 and prec1.

Note:

The non-regression tests (keywords VALE_CALC*) are always skipped in validation tests, but they must still be given (with any value) because the command catalog requires them. Validation tests are identified by testlist validation in their .export file. There is one exception: tests on character strings ( VALE_CALC_K ) are not skipped, because these tests have no tolerance/precision.

```text
◊  LEGENDE =
```

### 4.9 Keyword TEST_NAN

```text
|  TEST_NAN =          /  ‘NON’  ,                      [DEFAUT]
```

This keyword validates the NaN (Not-a-Number) handling of Code_Aster. It is to be used only for running tests. Using it must cause a fatal FPE (Floating Point Exception) error in debug mode in TEST_RESU.
