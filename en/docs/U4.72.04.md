# CREA_CHAMP operator

## 1 Purpose

Create a field of type `cham_no`, `carte` or `cham_elem`. A field can be created

- by assigning values on nodes or elements,
- by assembling (and / or combining) pieces of existing fields,
- by evaluating the functions of a field of functions to make it a field of reals,
- by changing the geometric representation of a field (nodes ⇔ Gauss points, for example),
- by extracting a field from a data structure of type SD_RESULTAT (`evol_ther`, `evol_noli`, `mode_meca`, ...).
- from the values held in a data structure of type TABLE,
- ...

This command can also be used to combine several fields linearly, and "more complicated" combinations are also possible: multiplication of fields ...

It produces a data structure of type `cham_no`, `carte` or `cham_elem`

Remark: The command is not reentrant except for the operations ASSE and COMB. In that case, the keyword CHAM_GD is required.

## 3 Operands

### 3.1 General operands

#### 3.1.1 Operand TYPE_CHAM, assigning a type to the result field

This (required) keyword is first used to type the result field of the command. It is made of 2 "words" joined by an underscore (_):

```text
TYPE_CHAM= 'XXXX_GD'où:
XXXX=     /  'NOEU'       Cham pauxnœ uds                  (cham_no)
```

| / 'CART' | Field constant per element | (`carte`) |
|---|---|---|
| / 'ELNO' | Element field at element nodes | (`cham_elem`) |
| / 'ELGA' | Element field at Gauss points (`cham_elem`) |   |
| / 'ELEM' | Field constant per element | (`cham_elem`) |
| GD= | / 'DEPL_R' | displacement |
| / 'SIEF_R' | stress |   |
| / 'TEMP_R' | temperature |   |

```text
/  'FLUX_R'     flux
/  ...
```

The type of the result field is deduced from this information given by the user. For example:

```text
TYPE_CHAM= 'NOEU_DEPL_R'         ->    cham_no   (DEPL_R)
TYPE_CHAM= 'CART_SIEF_R'         ->    carte     (SIEF_R)
TYPE_CHAM= 'ELNO_EPSI_R'         ->    cham_elem (EPSI_R)
TYPE_CHAM= 'ELGA_VARI_R'         ->    cham_elem (VARI_R)
```

This keyword also tells the command what the nature of the result field must be. It is essential for the operations 'AFFE', 'ASSE' and 'DISC'.

Examples:

```text
OPERATION= 'AFFE'  + TYPE_CHAM= 'CART_DEPL_R'  => une carte de DEPL_R.
OPERATION= 'ASSE'  + TYPE_CHAM= 'NOEU_EPSI_R'  => un cham_no de EPSI_R.
OPERATION= 'DISC'  + TYPE_CHAM= 'NOEU_SIEF_R'  => un cham_no de SIEF_R.
```

There are only two operations for which this keyword is a useless (but required!) constraint for the user (OPERATION='EVAL' and OPERATION='EXTR'), because for these two operations the nature of the result field is set by the choice of operation.

Filling in the keyword TYPE_CHAM is (unfortunately) tedious for OPERATION='EXTR'. It follows from the keyword NOM_CHAM. The correspondence is given in [3.9.1].

Important remark

Whether a `cham_elem` of any physical quantity can be created depends on the (software) development state of the finite element types of the model. Not everything is possible yet; for example, to create a `cham_elem` of FLUX_R on a model holding DKT elements, this finite element must have been designed to do so (which is not the case today).

The precise list of quantities allowed for each finite element type cannot be given here. Roughly:

- for isoparametric mechanical elements, the quantities allowed are: GEOM_R , INST_R , NEUT_R , NEUT_F , EPSI_R , SIEF_R , VARI_R , DOMMAG and HYDR_R ,
- for isoparametric thermal elements, the quantities allowed are: GEOM_R , INST_R , NEUT_R and NEUT_F .

#### 3.1.2 Operand CHAM_GD

With the operations ASSE and COMB, an existing field can be reused. In that case, give here the field that is reused.

#### 3.1.3 Operand MAILLAGE = mailla

When creating a CHAM_NO or a CARTE, you generally have to give the mesh the field is based on. Use the keyword MAILLAGE for this.

#### 3.1.4 Operand PROL_ZERO

When creating a CHAM_ELEM, the values present in the field are determined by the finite elements of the model. For example, a SIGM_ELGA field on a 2D model must hold the 4 components SIXX, SIYY, SIZZ and SIXY. If the construction of the field cannot compute all the expected values, there is a problem. If the keyword PROL_ZERO is 'OUI', the missing values are set to zero. If the keyword PROL_ZERO is 'NON', the code stops with an error.

This problem also concerns (more rarely) the CHAM_NO when one wants to impose the numbering of their components (see the keywords NUME_DDL and CHAM_NO).

#### 3.1.5 Operands MODELE, OPTION

When creating a CHAM_ELEM, give the finite elements on which the field is defined. Use the keyword MODELE for this.

To describe the structure of a CHAM_ELEM, giving (through the MODELE) an element type for each element is not enough, because an element type can have several "shapes" for a given quantity. To create the field wanted, the user can use the keyword OPTION. If for example the user writes: X= CREA_CHAMP(... MODELE=mo, OPTION='SIEF_ELGA', ...) , the field created by CREA_CHAMP has the same shape as if it had been computed by CALC_CHAMP / CONTRAINTE='SIEF_ELGA'. If the user does not use the keyword OPTION, CREA_CHAMP chooses (if it can) a default shape.

Remark: for the operation 'ASSE', when assembling `cham_elem` fields, it is generally better not to give the keyword OPTION. The option chosen is that of the field given in the 1st occurrence of the factor keyword ASSE, if the quantity of this field is the same as that of the result field.

#### 3.1.6 Keywords AFFE_SP / CARA_ELEM

The (non-repeatable) factor keyword AFFE_SP asks for the creation of a `cham_elem` with «sub-points» (for structural elements: multilayer shells, multifiber beams, …). In the `cham_elem` produced, each point (node or Gauss point) is represented by n sub-points (n being set by the user's choices in the command AFFE_CARA_ELEM). The n sub-points of a point carry the same components (with the same values).

The keyword CARA_ELEM is required: it is the name of the data structure of type `cara_elem` that gives the number of sub-points.

#### 3.1.7 Keywords NUME_DDL and CHAM_NO

These two keywords impose a numbering for the result field (if it is a CHAM_NO). They give a numbering "template" for the result field.

<!-- page 10 -->

If NUME_DDL= nu is given, the numbering of nu is used. This is only valid for displacement fields (physics 'MECANIQUE' ), temperature fields (physics 'THERMIQUE' ) or acoustic pressure fields (physics 'ACOUSTIQUE').

If CHAM_NO= chno is given, the numbering of chno is used.

In the latter case, the numbering given (object of type PROF_CHNO) is duplicated so that the field created is self-contained.

If Lagrange multipliers from boundary conditions with Lagrange-multiplier enforcement are present, the operator performs a check. Indeed, if the fields considered do not satisfy the same boundary conditions, they are not compatible. A warning is then issued: the Lagrange multipliers are set to zero in the resulting field.

#### 3.1.8 Operand TITRE = titr

Title to give to the result field [U4.03.01].

#### 3.1.9 Operand INFO = /1 /2

```text
INFO = 1
```

No print.

```text
INFO = 2
```

Prints the result field to the 'MESSAGE' file.

### 3.2 Operand OPERATION = /'AFFE' / 'ASSE' / 'EVAL' / 'DISC'

```text
/ 'EXTR' / 'R2C' / 'C2R' / 'COMB'
```

This operand chooses the "mode" of construction of the result field. A field can be created:

- by assigning values on nodes or elements (OPERATION='AFFE'),
- by assembling pieces of fields defined on pieces of meshes (OPERATION='ASSE'),
- by changing the geometric representation (discretization) of a field (nodes <-> Gauss points, for example) (OPERATION='DISC'),
- by extracting a field from a data structure of type SD_RESULTAT (`evol_ther`, `evol_noli`, `mode_meca`, ...) (OPERATION='EXTR').
- by extracting numeric values from a table whose columns have predefined names:

```text
‘MAILLE’, ‘NOEUD’…
```

- by combining fields linearly (OPERATION='ASSE'),
- by "combining" (multiplication, exponential, ...) fields (OPERATION='EVAL'),
- by evaluating the functions of a field of functions to make it a field of reals (OPERATION='EVAL'),
- by turning a real nodal field into a complex field (or the reverse) (OPERATION='R2C'/'C2R'),
- by a linear combination of several `cham_no` fields with the same numbering (OPERATION='COMB'). Unlike the operation 'ASSE', the result field keeps the Lagrange degrees of freedom associated with the Lagrange-multiplier enforcement of the boundary conditions.

### 3.3 Operands for OPERATION = 'AFFE'

This operation assigns values (real, integer, complex or function) on geometric entities (nodes or elements) of a mesh.

<!-- page 11 -->

The physical quantity of the field is given implicitly by the keyword TYPE_CHAM (above).

#### 3.3.1 Factor keyword AFFE

The operands are grouped under the factor keyword AFFE. This keyword can be repeated. The overloading rule applies between the occurrences of the keyword AFFE: if a geometric entity is assigned several times, the last assignment wins.

#### 3.3.2 Operands TOUT='OUI', GROUP_MA and GROUP_NO

The geometric entities to assign are given by the operands TOUT='OUI', GROUP_MA, and GROUP_NO.

If TYPE_CHAM='NOEU_xxx', nodes are assigned; the operand GROUP_MA can be used and means that all the nodes of the given elements are assigned. If TYPE_CHAM:'EL.._xxx' (or 'CART_xxx'), elements are assigned; the operand GROUP_NO is then forbidden.

Remark: For the factor keyword AFFE, the keyword TOUT='OUI', means:

- "all the nodes of the mesh" for `cham_no` fields,
- "all the elements of the mesh" for maps,
- "all the elements of the model" for `cham_elem` fields,

#### 3.3.3 Operand NOM_CMP

The names of the components to assign are given by the operand NOM_CMP. If the quantity is 'VARI_R', the components must be named 'V1', 'v2', 'V3', … If the quantity is 'VARI_R' and PROL_ZERO='OUI' is chosen, the components whose number is below the largest number assigned are set to zero. For more details see the document [U2.01.09].

#### 3.3.4 Operands VALE, VALE_I, VALE_C or VALE_F

The values to assign are given by the operands VALE, VALE_I, VALE_C or VALE_F depending on the nature (real, integer, complex, function (or formula) ) of the components of the quantity (DEPL_R : real, DEPL_C : complex, TEMP_F : function / formula , ....).

#### 3.3.5 Remark

The persistence rule (see U1.03.00) applies to the components that can be assigned.

#### 3.3.6 Examples

Creating a nodal displacement field, with an imposed numbering of the field (that of cnomod):

```text
DEPL1 = CREA_CHAMP( OPERATION= 'AFFE',
          TYPE_CHAM='NOEU_DEPL_R' , MAILLAGE = MA, CHAM_NO= CNOMOD,
          AFFE= (
          _F (TOUT='OUI', NOM_CMP=('DX','DY','DZ'), VALE=(0.,0.,0.),),
          _F (GROUP_MA=('GM1',’GM2’) , NOM_CMP= 'DX' , VALE= 3.5e-2),
          _F (GROUP_NO=('GN5',’GN7’,’GN9’) , NOM_CMP= 'DY' , VALE= 1.6e-2),
                   )
)
```

Creating a temperature map (functions):

```text
TEMPF = CREA_CHAMP( OPERATION= 'AFFE',
          TYPE_CHAM='CART_TEMP_F' ,  MAILLAGE = MA,
          AFFE=(_F( TOUT='OUI', NOM_CMP=('TEMP'),VALE_F= F1),
                _F( GROUP_MA=(‘GM1’,’GM2’),NOM_CMP=('TEMP'),VALE_F=F2),)
)
```

### 3.4 Operands for OPERATION = 'ASSE'

#### 3.4.1 General

This operator "assembles" "pieces of fields" to make a new one. Each occurrence of the keyword ASSE defines a piece of field. A piece of field is the restriction of an existing field (`carte` / `cham_no` or `cham_elem`) to a set of geometric entities (elements or nodes) and to a set of components.

The occurrences of the keyword ASSE follow an overloading rule if the pieces overlap.

Currently, one can build:

- a `cham_no` by assembling pieces of `cham_no` fields.
- a `cham_elem` by assembling pieces of `cham_elem` fields and/or maps.
- a `carte` by assembling pieces of maps and/or `cham_elem`/ELEM fields.

The operation 'ASSE' can also change the physical quantity of a field, for example turning a strain field (EPSI_R) into a stress field (SIEF_R). Use the keywords NOM_CMP and NOM_CMP_RESU for this.

The pieces of fields can be assembled by summing them (keywords CUMUL and COEF_R). This lets the command make linear combinations of CHAM_NO or CHAM_ELEM fields.

#### 3.4.2 Operands MAILLAGE, MODELE

Same use as for OPERATION= 'AFFE' [§3.3.1] and [§3.3.2].

#### 3.4.3 Operands for the factor keyword ASSE

Each occurrence of the factor keyword ASSE defines a piece of field that is assembled into the result field.

##### 3.4.3.1 Operand CHAM_GD = ch1

ch1 is the (existing) field from which a piece of field is made.

##### 3.4.3.2 Operands TOUT ='OUI', GROUP_MA and GROUP_NO

These operands define the geometric restriction of the field ch1. If ch1 is a CHAM_NO, all these operands can be used. If ch1 is a CHAM_ELEM (or a CARTE), the operand GROUP_NO cannot be used. The keyword TOUT='OUI' means here: «all the nodes, elements that carry components (of the list NOM_CMP) in the field ch1».

##### 3.4.3.3 Operands NOM_CMP and NOM_CMP_RESU

The operand NOM_CMP gives the components to which the field ch1 is restricted. If NOM_CMP is absent, all the components of ch1 are taken.

### 3.8 Operands for OPERATION = 'NORMALE'

This operation computes the "normal" vectors to the facets of a model. With the keywords MODELE and GROUP_MA, the user gives the name of the model concerned and the "facets" whose normals are wanted. The "facets" can be "skin" elements of a 3D mesh or plate / shell elements. For 2D meshes, the "facets" are line elements.

The field produced is a `cham_no` (quantity GEOM_R) whose components are named X, Y, Z. The normal carried by a node is the mean of the normals of the facets sharing this node. The "normal" vector has length 1.

#### 3.9.6 Computing a field holding the "extrema" of an SD_RESULTAT

The idea is to create a field holding, at each point in space, the extreme value met during a transient (or the time at which this value was met).

Today this section only concerns results of type `evol_ther`, `evol_elas`, `evol_noli` and `dyna_trans`. The fields are always of "real" type.

Give:

- the step indices that define the transient: TOUT_ORDRE, LIST_INST,
- the type of extremum chosen: TYPE_MAXI = 'MAXI', ..., 'MINI_ABS', 'NORM_TRAN',
- what is wanted: the extreme value or the time at which this value is reached (TYPE_RESU).

##### 3.9.6.1 Operand TYPE_MAXI

| / 'MAXI' | the maximum reached by the components during the transient is considered, |
|---|---|
| / 'MAXI_ABS' | the maximum reached by the absolute value of the components during the transient is considered, |
| / 'MINI' | same for the minima, |

```text
/ 'MINI_ABS'
```

/ 'NORM_TRAN' the maximum reached by the following quantity is considered:

```text
DX**2 + DY**2 + DZ**2.
```

- for the 4 values 'MAXI', ..., 'MINI_ABS', the components of the field are processed independently of each other: the extreme values may not be reached at the same time,
- the fifth possible value, 'NORM_TRAN', is only possible for `depl_R` fields. At a given point, the time at which the norm of the translation vector is maximum is found, and all the components of the field at that time are copied into the result field.

##### 3.9.6.2 Operand TYPE_RESU

/ 'VALE' , the result field holds the extreme values met during the transient,

Remark:

Even if the extremum was obtained with an absolute value ('MAXI_ABS' or 'MINI_ABS'), the value stored is signed. Use VALE_ABS to get the absolute value.

/ 'INST' , the result field holds the times at which the extreme values were met.

Remark:

If for example:

```text
•    NOM_CHAM  = 'FLUX_ELNO',
•    TYPE_RESU = 'INST',
```

The result field is a field of type FLUX_R that holds time values!

##### 3.9.6.3 Operands TOUT_ORDRE / LIST_INST / LIST_FREQ / PRECISION / CRITERE

##### 3.9.7.4 Extracting a stress field from a table

Take the file (fort.81) holding the image of the following table:

#DEBUT_TABLE
