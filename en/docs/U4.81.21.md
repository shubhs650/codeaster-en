# POST_RELEVE_T operator

## 1 Purpose

Extract values of field components and compute means and invariants. The values are collected on nodes, elements, or polylines joining nodes. With the same command they can also be used for:

- calculations of:
  - means,
  - resultants and moments of vector fields,
  - invariants of tensor fields,
  - the directional trace of fields,
  - extrema and the arithmetic mean over nodes or elements
- expression in the GLOBAL, LOCAL, POLAIRE, UTILISATEUR or CYLINDRIQUE coordinate systems.

POST_RELEVE_T produces an object of type table, which can be printed with IMPR_TABLE [U4.91.03].

## 3 How to use POST_RELEVE_T: operand ACTION

The post-processing done by POST_RELEVE_T needs three pieces of information:

- location,
- object,
- nature.

Each occurrence of the factor keyword ACTION defines this triplet.

The location of the post-processing is a geometric figure joining the post-processing points. It is defined with the keyword GROUP_NO.

The object of the post-processing is defined by choosing a field, components and possibly associated quantities, selected with different keywords.

The fields are chosen with one of the keywords:

RESULTAT and the keywords that select the nodal fields or the element fields of the `resultat` data structure.

CHAM_GD a field produced by an elementary operator, or extracted from a result object with CREA_CHAMP [U4.72.04].

the components with:

```text
TOUT_CMP
NOM_CMP
```

and the associated quantities with:

```text
INVARIANT
ELEM_PRINCIPAUX
TRAC_NOR
TRAC_DIR etDIRECTION
```

RESULTANTE and, optionally, MOMENT and POINT

The nature of the post-processing is the operation: keyword OPERATION

- extraction of values: 'EXTRACTION'
- calculation of means (in the sense of integration), minimum and maximum over an ordered group of nodes: 'MOYENNE'
- calculation of minimum and maximum over groups or entities: 'EXTREMA'
- calculation of arithmetic means over groups or entities:

```text
'MOYENNE_ARITH'
```

TOUT = 'OUI' is the standard case (all elements are considered). These keywords can only be used with GROUP_NO.

Remarks: Using GROUP_MA with the operation MOYENNE is not recommended unless the elements are segments. Recall that the operation MOYENNE computes quantities along a length L. Discrete elements assigned directly on the nodes of the mesh (AFFE_MODELE / NOEUD), which are not recommended anyway, are ignored by the post-processing.

## 6 Nature of the post-processing

### 6.1 Operand OPERATION

```text
♦  OPERATION =
   |  'EXTRACTION'
```

The extraction operation on a field retrieves the values of one or more components, or of quantities derived from these components, at the points of the post-processing location.

For an extraction on a `cham_elem`, the values of the components extracted from this field are computed as follows:

- If the post-processing location is given by the keyword GROUP_NO, at each node the components are averaged over all the elements sharing this node. When extracting a field of type ELNO, the same values are obtained by giving the field of type NOEU.

Remark:

Averaging at the nodes fields computed in local coordinate systems is only valid if the angles between these coordinate systems are small. Otherwise it has no meaning.

If the post-processing location is defined by GROUP_NO = (GN1,GN2,GN3,GN4,GN5), the values are averaged over all the elements of the mesh above.

If the post-processing location is defined as the segment with origin N1 and end N5 , the values are averaged over the hatched elements.

For quadratic elements (with middle nodes), the mean at the corner nodes can give larger weights to some elements (depending on the subdivision) than at the middle nodes, which average over 2 elements (hence with the same weight). Oscillations can therefore appear between the values at the corners and at the middles.

## 8 Verification phase

The command checks that all the labels are different.

### 8.1 At execution

This phase checks that the arguments are consistent with each other. It covers all the occurrences of the factor keyword ACTION. There are 2 groups of checks.

The first group is common to the arguments of the keywords CHAM_GD and RESULTAT (which are mutually exclusive) and is limited to the following check:

- acceptability of the components: the requested components must be present in the description catalog of the quantity processed,

The second group is specific to the keyword RESULTAT and is limited to the checks:

- acceptability of the symbolic field: the symbolic field given to the keyword NOM_CHAM must exist for the type of `resultat` object given to the keyword RESULTAT,
- existence of at least one data structure for the symbolic field processed.

At the end of the verification phase, at execution, one of two things happens:

- all the occurrences of ACTION are correct and the operations are run,
- at least one occurrence of ACTION is incorrect: a fatal error message is produced and the command stops. Information is given on the nature of the errors and how to correct them.

<!-- page 19 -->

### 8.2 During processing

A further verification filter applies, but it never stops the command. This filter is limited to the following checks:

- existence of the data structure given by CHAM_GD or RESULTAT, and of one of the keywords that give access into a RESULTAT data structure. If this fails, a message is issued and the next occurrence is processed,
- for a calculation of tensor invariants, the object processed must be a second-order tensor,
- for a mean calculation or a value extraction, the components to process must have been computed on the post-processing location. If this check fails, a message details the components that are not available for the elements or nodes of the post-processing location.

If this last filter finds no reason the calculation cannot be done, the post-processing is run and the results are inserted into the table.
